# 协议：两通道诊断流程（定义 + 自采侧样本内演示）

**冻结日期**：2026-09-03
**状态**：`PROTOCOL_FROZEN_BEFORE_NUMERIC_RUN`
**性质**：把"逐数据集提升各自识别率"的**流程**定义冻死，并在自采跨轮次任务上做**样本内演示**。
本协议**不声称验证**该流程——验证在 UNSW（20 天）与 CIC（30 天）上进行，理由见 §3.3。
不重开任何既有冻结判定；不恢复 CPD 与 EC-MDM 的机制、预测或部署身份。
**裁定方**：主线侧。

## 0. 为什么是这个形式

三条已测事实决定了流程只能有两个坐标：

```
① 元层损伤   源域元层重映射 m_src[i→j] 对目标域逐类对伤害 Spearman +0.798
             控制 m_src 后 f_ji_src 只剩 +0.064（即后者是前者的代理变量）
② 表示损伤   源域拟合的多变量类对判别 CV AUC 0.93–0.98，目标域 0.62–0.68
             39 个困难簇组合中 13 个目标 AUC < 0.5（边界反号，最低 0.0000）
             易类对 5/5 组合 1.0000 → 1.0000，零反转
③ 两者不相关 auc_tgt ↔ m_src_max  Spearman −0.153（n=35）
             auc_tgt ↔ harm_max    −0.212     分组比较方向与相关系数相反
```

③ 是本协议的依据：两个损伤通道近乎正交，**不能合成一条链，只能作两个坐标交替优化**。

干预侧已有的量级估计（94→59，150 个 OOD 任务）：

```
RF 的 OOD 改善        +0.0591     RF 无元层，这一份纯表示
stacking − RF        +0.1026     只有带元层的模型拿得到
stacking 总计        +0.1617     145/150 任务为正
IID 代价             −0.037 ~ −0.056（四模型）
```

**目标不是提出更好的模型，而是一个能在各自数据集上把总体识别率推到局部最优的流程。**
所以跨数据集**不比较特征、不比较幅度**——每个数据集得到自己的答案，只比较"流程有没有让它自己变好"。
这使 61 列不可通约的限制在构造上不适用。

## 1. 唯一问题

在只使用源域/历史轮次信息的前提下，交替优化两个坐标，能否把跨轮次的总体识别率
推到"任一单坐标移动都不再改善"的点，且该点优于每个单坐标最优与朴素起点。

## 2. 流程定义（数据集无关，本协议冻结后对所有数据集一致）

### 2.1 特征族导出规则（机械，禁止手工调整）

```text
1. 元数据列表按数据集声明，且必须排除任何时间戳/序号列
   （自采：label,round,traffic,filter_mode,source_file,window_id,window_start,window_end
     UNSW：device,day,label,source_file,window_id,window_start,window_end,window_start_epoch）
2. 剩余数值列按「列名第一个下划线段」分组
3. 成员数 < 2 的组全部并入单一组 `singletons`
4. 组按成员数降序、同数按名字升序排列，落盘
```

该规则在两个数据集上的实测输出（结构性，不含任何结果）：

```text
自采 94 列 → 10 组  subtype16 len14 singletons13 interarrival12 subwin9 rssi8 burst7 up7 down6 unique2
UNSW 62 列 → 7 组   len14 interarrival12 subwin9 burst7 singletons7 up7 down6
```

**已知限制**：族级搜索无法定位埋在 `singletons` 里的单列元凶。这是把搜索空间压到
可诚实检验规模的代价，必须写入限制章节。

### 2.2 簇导出（沿用既有冻结规则，不改）

`f_ij = CM_rf[i][j]/rowsum(i)`，`max(f_ij, f_ji) >= TAU = 0.10` 连边，取节点数 ≥2 的连通分量。

### 2.3 坐标 1 · 表示（诊断 + 动作）

```text
诊断  对每个簇内无序类对 (i,j)：
        源域上只用 {i,j} 两类窗口、全部当前特征联合，拟合 LogisticRegression
        (max_iter=2000, C=1.0, random_state=42, n_jobs=1)，源域统计量标准化（sd=0 的列除以 1.0）
        AUC_tgt = 该边界在目标域 {i,j} 窗口上的 AUC
      对每个族 F：去掉 F 的列后重拟合，ΔAUC_tgt(F) = AUC_tgt(去 F) − AUC_tgt(当前)
动作  两段制。代理量只用于**提议**，判定权交给真实目标。
      提议  S(F) = ΔAUC_tgt(F) 在全部（任务, 簇内类对）组合上求和
            候选族按 S(F) 降序排列，只考虑 S(F) > 0 的族
      接受  对排在最前的候选 F，重训完整四模型集（rf/xgboost/lightgbm/stacking），
            在 9 个跨轮次任务上取逐任务 macro-F1 的变化 Δ_t(F)，令
              G = Σ_{Δ_t>0} Δ_t      L = Σ_{Δ_t<=0} Δ_t      W = min_t Δ_t
              A = mean{Δ_t : Δ_t > 0}
            三条同时满足才删除 F：
              (i)  Σ_t Δ_t > 0
              (ii) G / |L| >= 3
              (iii) |W| <= 0.5 × A
            不满足则跳过 F，试下一个候选；全部候选都不满足即停止
      每次只删一个族；最多删 3 个族（防止退化到空特征集）
```

**为什么损伤上限放在 macro-F1 而不是代理量**（运行前记录，避免事后合理化）：
逐类对 AUC 是代理。已实测：删 `rssi(8)` 在代理量上 `S=+6.3892`、`G/|L|=3.78`（过），
但 `W=−0.2951` 超过上限 `0.5×A=0.2172`（不过）。而**全部 19 个受损组合都落在
"边界本来就迁得动"的一侧**（目标 AUC 均值 0.9161），反转侧 13 个组合零受损、最小收益 +0.3449；
且 98% 的损失集中在 `|S|=1`（−2.2521 / −2.2981，最差 −0.2951，而 `|S|=2` 最差仅 −0.0175）。
一个类对从 AUC 0.9879 掉到 0.6948，在有另外 86 列可用的完整多类模型里未必体现为 macro-F1 损失。
**用严格上限去卡代理量会否掉一个可能在真实目标上无害的动作**，故上限只施加于 macro-F1。
`(ii)` 的 3 与 `(iii)` 的 0.5 由用户在只见过代理量数字、未见过任何 macro-F1 评估结果时选定
（选的是三个候选取法中最严格的一个），此披露一并冻结。


### 2.4 坐标 2 · 元层（诊断 + 动作）

```text
诊断  在源域 OOF 上（标签为源域自身，零目标标签）：
        基共识 = 三个基模型 OOF argmax 一致；元模型预测 = final_estimator_ 作用于 OOF 元特征
        m_src[i→j] = 基共识为 i 的窗口中元模型改判为 j 的比例
        m_src_max  = 簇内全部有序类对的 m_src 最大值
动作  两段制，与坐标 1 同构：诊断只**提议**，判定权交给可用的有标签证据。
      提议  m_src_max > 0  →  提议"不使用 stacking，改用按源域 OOF macro-F1 选出的最佳基模型"
      接受  在**内层历史 LORO 任务**上核验：只用该任务的源轮次两两组成 LORO
            （例：目标为 R4、源为 {R2,R3} 时，内层任务是 R2→R3 与 R3→R2，全程不触碰 R4），
            比较 stacking 与该配置的 macro-F1；仅当后者不劣于前者时接受提议
      |S|=1 的任务无内层 LORO 可用，故坐标 2 在该档**不执行任何动作**并记
            `COORD2_UNAVAILABLE_SINGLE_SOURCE`（与 §10 使用条件一致）
```

无参数，无从事后调阈值。**选择模型与核验都不读目标标签**——`m_src` 只用源域 OOF，
内层 LORO 只用源轮次；实现审阅逐行核对这一条（§5.3）。

**两个坐标都改成"诊断提议 + 真实目标接受"之后，流程在它所依据的有标签证据上
按构造是单调的**：任何一步都不会被接受，除非它在该证据上改善跨轮次 macro-F1。
必须同时声明这句话的边界——**在历史证据上单调 ≠ 在真正未见的新环境上单调**。
后者是 §4 五点对照要检验的经验问题，不是构造保证。


### 2.5 交替与停止

```text
坐标 1 → 坐标 2 → 坐标 1 → …，任一坐标不再改变配置即停止；上限 3 轮。
两个顺序都跑：1→2 与 2→1，终点不同即记 `PATH_DEPENDENT`，不得只报有利的那个。
```

## 3. 自采侧实例化（本协议的运行部分）

### 3.1 任务集

按用户口径，**新环境 = 跨轮次**。只取源与目标轮次全部落在 `{R2,R3,R4}` 内的任务：

```text
|S|=2  g0_R2_R3_to_R4  g0_R2_R4_to_R3  g0_R3_R4_to_R2
|S|=1  g0_R2_to_R3  g0_R2_to_R4  g0_R3_to_R2  g0_R3_to_R4  g0_R4_to_R2  g0_R4_to_R3
```

R5（位置变更）与 R6/R7（操作抖动）**不进本协议**——它们是泛化环境，另案。
必须写入限制：`docs/RSSI特征分析.md` 记录删 RSSI 在 R5（0.6745→0.6531）与
R6+R7（0.7550→0.7310）上**有害**，方向与跨轮次相反，且该形态在 94 维下从未重测。

### 3.2 特征缓存与模型

`results/robust_v2/raw_all/features_raw_all_w10.csv`（11303×102）；
`feature_columns` / `clean_x` / `build_model` / `SimpleStackingClassifier` 全部 import 不重实现；
`random_state=42`、`n_jobs=1`、线程钉死。

### 3.3 本协议**不构成验证**，理由必须原文写入判定书

诚实的验证要求留出一个轮次当"新环境"、流程只用其余轮次。自采只有 3 个同条件轮次，
留一之后历史只剩 2 个轮次 → 流程内部的诊断任务全是 **|S|=1**。而 |S|=1 时
**坐标 2 的诊断结构性失效**（实测 30/30 个任务 `m_src_max` 精确为 0.0000，
因为单轮次时 stacking 的 OOF 分组退化为轮内时间块，源域 OOF 中不存在跨轮次混淆；
同时 gap_H 仍为 −0.0867，损伤照旧发生）。

**所以自采面板在结构上无法验证这个流程。** 本协议只做两件事：把流程定义冻死，
并报样本内演示。验证必须在有足够多同条件轮次的数据集上做——UNSW 20 天、
CIC 2-Idle 30 天，留一之后历史仍有 19/29 天，|S|≥2 唾手可得。

样本内演示与留一演示**两者都报**，且必须逐项标注哪一个是样本内。

## 4. 评估：五点对照与判据

对每个任务、每个配置，指标 = 目标域 macro-F1（labels 固定为该任务全部类，zero_division=0）。
**唯一被优化的目标是跨轮次 macro-F1。** 同轮次（IID）数字只作护栏与天花板参照，不进任何判据
（理由：部署形态是训一次、跑后续轮次，从不在同轮次 regime 内运行）。

| # | 配置 | 含义 |
|---|---|---|
| ⓪ | 源域 CV 选模型（候选含 stacking） | **标准做法**：源域 5 折 CV（按训练轮次分组，`|S|=1` 时按时间块）选 macro-F1 最高的模型，全部特征 |
| ⓪′ | 按 RF 重要性做特征选择 + 源域 CV 选模型 | **标准做法**：源域拟合 RF，按重要性降序保留累计重要性 ≥0.95 的最小列集，再按 ⓪ 选模型 |
| ⓪″ | CORAL / SA（已完成，直接引用） | 已发表基线，`DA_DOES_NOT_HELP`，`coral_raw` −0.0365、`sa_zscore` −0.0893 |
| ① | 全部特征 + stacking | 朴素起点 |
| ② | 全部特征 + 不堆叠 | 只优化坐标 2 |
| ③ | 流程删列 + stacking | 只优化坐标 1 |
| ④ | 流程删列 + 不堆叠 | 流程终点 |
| ⑤ | 逐任务事后最优（用目标标签在 ①–④ 中选） | oracle 上界 |

⓪ 与 ⓪′ 是**真正的对手**——它们是一个有能力的从业者在不知道本流程时会做的事。
`①` 只是朴素默认。⓪′ 的预期行为已知：`rssi_*` 占 RF 重要性质量 27.4%、排 #2/#3/#4、
`selected_rate` 恒为 1.0，故**按重要性选择会保留 rssi**，而本流程的诊断要删掉它。
这一对照使贡献可辨识：标准选择优化源域表现，失效在迁移。

**判据（运行前定死）**，全部在 9 个跨轮次任务上按算术均值：

| # | 判据 | 门槛 | 不通过 |
|---|---|---|---|
| 1 | 优于标准做法 | `④ > ⓪` 且 `④ > ⓪′` | `NO_GAIN_OVER_PRACTICE` |
| 2 | 优于朴素起点 | `④ − ① >= +0.05` | `PROCEDURE_NO_GAIN` |
| 3 | 联合优于每个单坐标 | `④ >= max(②, ③)` | `NO_JOINT_GAIN`（仍报两个单坐标值） |
| 4 | 与 oracle 的差距 | `⑤ − ④ <= 0.05` | 记 `REGRET_LARGE`，不阻断，写入限制 |
| 5 | 特征集护栏 | 每个配置的 IID macro-F1 `>=` 其跨轮次 macro-F1 | `FEATURE_SET_DEGENERATE` |

判据 1 是**主判据**——它是唯一能区分"流程有贡献"与"重新发现了标准做法"的检验。
判据 2 的 +0.05 由已测量级定：`gap_vs_best_base` 在 OOD 上 −0.0729 → −0.0062，
单靠坐标 2 就应越线；低于 0.05 说明流程没兑现已知可得的收益。


**并报，无论方向（预注册要求）**：IID 代价（12 个 IID 任务上 ④ − ①）；
逐任务表；坐标 1 实际删掉的族序列与每个候选族的三条接受条件实测值；
坐标 2 逐任务的 `m_src_max` 与是否触发；`PATH_DEPENDENT` 与否。

**必须按 `|S|` 分层并报**（`|S|=1` 六任务 / `|S|=2` 三任务分别给出 ①–⑤ 与三条判据），
理由见 §9 的使用条件：两个坐标的信号都依赖 `|S|>=2`，混在一起报会掩盖这一点。
流程本身**不限定** `|S|>=2` 才运行——限定会使自采只剩 3 个任务，样本内演示过薄；
但分层数字必须让读者自己看到分界在哪。


## 5. 硬门（任一失败即停，不写结论）

1. **无泄漏**：训练轮次与目标轮次交集为空；窗口唯一键 `(round, source_file, window_id)` 无重复
   （并报原键 `(round, window_id)` 计数——该键非唯一，见 `PROTOCOL_DA_BASELINES_20260903.md` §10）。
2. **元数据不入特征**：族导出后逐项核对不含任何时间戳/序号列，落盘列清单。
3. **坐标 2 无目标标签**：`m_src` 与最佳基模型的选择只读源域 OOF；实现审阅逐行核对。
4. **有限值**：`clean_x` 后 0 NaN / 0 inf；标准化后同样校验。
5. **双跑**：全部判定性产物 md5 逐字节一致。`OMP=MKL=OPENBLAS=1` 且 `n_jobs=1`，不与其他作业并行。
6. 全程禁网、禁代理。解释器 `~/anaconda3/envs/iotcls/bin/python`。

## 9. 解释边界

本协议只裁定：该流程在自采 94 维、9 个跨轮次任务、RF/XGB/LGB/stacking 模型集下，
样本内能否把总体识别率推到局部最优。它**不构成**：流程的验证（§3.3）；
泛化性的证据；R5/R6/R7 泛化环境上的结论；对同日内在难度的改善
（UNSW 同日 0.8793 说明约 0.12 的缺口在跨天之前就存在，本流程不针对它）；
无标签部署方法的成立；层一/层二/层三任何一层的新证据。

"局部最优"只指"任一单坐标移动不再改善"，不含全局最优的含义。
真正的对手是**朴素起点**（全特征 + stacking），因为 always-RF 本身就是流程的产出而非先验已知。

## 10. 流程的使用条件（不是事后观察，是适用范围）

两个坐标的信号都依赖手上有 **≥2 个历史环境**，这一条必须随流程一起声明：

```text
历史 1 个环境    坐标 2 的 m_src_max 精确为 0（实测 30/30 个 |S|=1 任务），诊断无信号
                 坐标 1 的动作在此档最危险：98% 的代理量损失集中在 |S|=1
                 （损失合计 −2.2521 / −2.2981，最差单点 −0.2951）
                 → 此时只训练，不改配置
历史 ≥2 个环境   两个诊断都可用；坐标 1 的代理量损失在 |S|=2 上最差仅 −0.0175
                 → 可以开始优化
环境继续累积     元层损伤自身衰减：|S|=2 gap_H −0.1245 → |S|=3 −0.0805
                 推翻率 0.3503 → 0.1725
```

一个可能的原因（**猜想，非本协议裁定内容**）：两个源环境时模型在训练阶段就看见该特征族
在环境间变动，本就不重仓依赖它，删除代价小；单一源环境时该族在训练数据内看似完全稳定，
模型重仓押注，删除即失去无替代的判别力。本协议不检验这个原因。

## 11. 起点是任意的，终点因此是条件性的

`full94` 那 94 列是开发过程中累积出来的，**不是按任何准则选出来的最优同轮次特征集**。
所以：

1. 不得把 `full94` 的同轮次 0.9622 表述为"上限"或"最优"——它只是 `full94` 自己的 IID 数字。
2. 流程的终点是**从 `full94` 出发可达的**局部最优。换一个起点可能落到另一个局部最优。
   判定书必须写明终点对起点的条件性，与 `PATH_DEPENDENT`（坐标顺序）并列声明。
3. `⓪′`（按重要性选择）之所以是必要对照，正因为它是从同一起点出发的**另一条**移动路径。

**流程的定位（本协议只声明，不检验）**：两个坐标都改成"诊断提议 + 有标签证据接受"之后，
它是一个**改进算子**——在它所依据的证据上按构造不会接受使目标变差的移动。
因此"只要当前配置不在局部最优，应用它可能得到更优解；若已在局部最优，它什么都不做"
是构造上成立的陈述。**但它只在历史证据上成立**；能否迁移到真正未见的新环境，
是 §4 五点对照要回答的经验问题。跨数据集的适用范围由后续 UNSW / CIC 协议检验，
本协议不声称。

## 12. 修正条款（2026-09-03，运行前追加，与 §2.4 / §4 / §10 冲突处以本节为准）

### 12.1 坐标 2 增加第二个触发器：仲裁通道

运行前测量发现第三种失效模式：损失落在**基模型意见分歧**的窗口上，
而 `m_src` 只看一致窗口，对它完全盲。逐任务实测：`|S|=1` 六个任务的
`gap_vs_best_base` 均值 **−0.0571**，其损失几乎全部在分歧窗口，而 `m_src_max` 精确为 0。

```text
net_dis_src = ( #(嵌套元层错 且 源域最佳基模型对) − #(嵌套元层对 且 最佳基模型错) )
              / #(源域 OOF 分歧窗口)
嵌套定义：按 stacking 自身 OOF 分组留出一折（|S|>=2 按训练轮次；|S|=1 按 5 个等量时间块），
          用同超参 LogisticRegression(max_iter=2000, class_weight="balanced")
          在其余折上拟合、在留出折上预测
最佳基模型：按源域 OOF 准确率选，零目标标签
触发：net_dis_src > 0  →  提议"不堆叠"（与 m_src 触发器共用同一动作与同一接受核验）
```

**样本内版本已被自己的检验否掉，嵌套版本才可用**，两者一并记录：

| 版本 | Spearman → 目标域分歧组 Δ错误 | 触发 | 命中 | 漏报 |
|---|---:|---:|---:|---:|
| 样本内（`final_estimator_` 作用于其自身拟合过的 OOF 行） | **−0.219** | 0/9 | 0 | 7 |
| 嵌套（样本外） | **+0.692** | 7/9 | 6 | 1 |

只算有害侧的 `m_dis`（不减去有益侧）为 +0.051，**无信号**——必须用有符号的净值。
触发阈值保持无参数的 `> 0`：两个任务 net 恰为 0.0000，其中一个目标域受损（记为漏报，
如实报出）、另一个未受损；改成 `>= 0` 会把后者变成假阳，故不改。

**披露先后顺序**：该触发器的样本内版本先被我方检验否掉，之后用户提出"跨轮次验证呢"，
才测出嵌套版本可用。此顺序原文记录。

### 12.2 §10 的适用范围收窄

`|S|>=2` 这条硬限制**只约束映射通道**（`m_src` 需要源域 OOF 中存在跨轮次混淆，
单轮次里不存在，实测 30/30 个 `|S|=1` 任务精确为 0）。
**仲裁通道无此限制**——它测的是元层的过拟合，任何诚实的留出评估都能看见，
不需要跨轮次位移。故 `COORD2_UNAVAILABLE_SINGLE_SOURCE` 只适用于 `m_src` 触发器。
§10 中"历史 1 个环境时只训练不改配置"因此改为：坐标 1 与 `m_src` 触发器不可用，
`net_dis_src` 触发器可用。

### 12.3 首轮的解释边界：贪心失败不等于移动集合内无更优点

本轮只回答一个问题：**跨轮次 macro-F1 有没有提升。**

贪心搜索只走了族格中的一条路径。因此判据 1（`④ > ⓪` 且 `④ > ⓪′`）不通过时，
结论只能是**"贪心流程未超过标准做法"**，状态码记 `GREEDY_NO_GAIN_PENDING_LATTICE`，
**不得**记为"本移动集合内不存在更优点"。后者要由穷举 ≤3 删族的格
（`C(10,1)+C(10,2)+C(10,3) = 175` 个配置，约 11 小时）来判定，另立协议。

两句都必须写进判定书，不得只写一句：

```text
可以说   贪心流程在本轮口径下未超过标准做法
不可以说 本移动集合内不存在超过标准做法的点
```

同理，若判据 1 通过，也只能声称贪心路径上找到的点优于标准做法，
不得声称它是本移动集合内的最优点。

### 12.4 增加状态码 `ALREADY_AT_LOCAL_OPTIMUM`

若两个坐标都提议但接受核验全部拒绝，或都不提议，则流程未改变配置。
此时 `④ = ①`，判据 2 必然不过。这种情形记 `ALREADY_AT_LOCAL_OPTIMUM`，
与 `PROCEDURE_NO_GAIN`（提议被接受但收益不足）**分开报**——
前者是改进算子的正确行为（起点已在局部最优），后者才是流程失效。

### 12.5 取消簇导出：改为在全部类对上聚合（修一处泄漏）

**§2.2 与 §5.3 互相矛盾，必须在运行前解决。** §2.2 沿用既有冻结规则从
**目标域** RF 混淆矩阵导出簇，而 §5.3 要求坐标 2 全程不读目标标签。
既有的簇导出约定（含 `PROTOCOL_UNSW_META_MISMATCH_20260902.md` §3）用于**描述性**测量时无碍，
但作为**部署期流程**的一环就是泄漏——部署时拿不到目标标签，导不出簇。

**修正**：本协议**取消簇导出**。两个坐标的聚合范围改为**该任务的全部类对**：

```text
坐标 1   ΔAUC_tgt(F) 在全部无序类对上求和（原为仅簇内）
坐标 2   m_src_max = 全部有序类对的 m_src 最大值（原为仅簇内）
        net_dis_src 本就不依赖类对，无变化
```

**依据（运行前已测，故此修正不改变预期结论）**：易类对的贡献实测约为零——
删 `rssi(8)` 在易类对上 ΔAUC 均值 **0.000**、最大 **+0.0002**（n=5）；
易类的共识推翻为 **0/2101**。故把易类对并入聚合几乎不改变两个量，
但换来**零目标标签**与实现上取消一个环节。

簇的概念仍用于**结果解释**（报告时说明损伤集中在哪些类对上），但**不进入任何决策路径**。
`TAU=0.10` 在本协议中不再被使用。

**披露**：此矛盾是在实现阶段核对 §5.3 时发现的，发现时点在任何流程数字产生之前。
