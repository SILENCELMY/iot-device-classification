## 2. 核心论点：UDS 与 source Stacking 元层同源（负责人提出，Fable 5 认同并锐化）

**【假设】** —— 本节全部内容为**尚未检验的解释性论断**，可检验路径见 §4。

### 2.1 结构同源

两者都是"**在源域上确定的、关于基模型输出的关系，被原封不动搬到目标域使用**"：

- Stacking：`g_s : Z_t → ŷ`，其中 `Z_t` 是目标域三基模型概率拼接；
- UDS：以**源侧**分歧结构（OOF 预测构成）为参照，把目标侧分歧结构（测试预测构成）的偏离量映射为风险分。

两者共享同一个前提假设——**源域学到的那个关系在目标域仍然成立**。而 EC-MDM 的实测结论正是：
该假设在**类别条件**维度上失效。因此 UDS 有它自己的 EC-MDM。

### 2.2 用 M2 的阶梯说得更精确

`UDS = mean over 6 ordered model pairs of ||Off(G_src) − Off(G_tgt)||_F`（协议 §4.2）。两次压缩：
**对模型对求平均**销毁"哪个基模型变得不可信"，**Frobenius 范数**销毁类别维。

即：**UDS 在 M2 的阶梯上最多是 G 级（全局）构念，而现象需要 C 级（类别条件）**。
M2 量出的差正是 0.675 vs 0.891——UDS 结构上就丢掉了这一截，阈值怎么调都补不回来。

### 2.3 度量对象错位

UDS 度量的是**"变了多少"**（drift magnitude）；EC-MDM 指出要紧的是**"源关系还配不配"**（mismatch）。
二者不等价：大幅漂移若未打在元决策依赖的维度上可以无害；小幅漂移若正好打中则致命。
**UDS 在错误的坐标系里量漂移。**

### 2.4 与 G1 实测证据一致（三条）

1. 各 fold **内层最优** regret 0.0081–0.0238，5/6 fold **样本内**就达不到 0.01；网格 4830 点无并列歧义
   → 不是阈值没找好，**是那个标量里没有做决策所需的信息**；
2. oracle 分布（RF 63 / soft 49 / stacking 37）证明**可分空间存在**，失败不是"本来就无从选择"；
3. 条件 4 通过（存在正确的非 RF 选择）而条件 1–3 失败 → 信号**偶尔**够用、系统性不够用，
   符合"分辨率不足"而非"完全无信号"。

**因此：路线 A 的失败由 EC-MDM 可预测，而非运气不好。** 这构成独立线对主线负结果的**解释力**。

## 3. 由此得到的路线 C 形状（候选设计，**未冻结**）

### 3.1 一次方向修正（记录在案）

Fable 5 在讨论中先提出过"给 UDS 加分辨率、拿去做路线 C"，**方向错了**：那仍然是在漂移幅度的坐标系里
加精度。负责人的原意是反向的——**UDS 自己得了同一种病**。以下按修正后的方向写。

### 3.2 正确形状 = M2 的 C 级修正的**无标签版本**

三处关键差别（相对路线 A）：

| 维度 | 路线 A（已判失败） | 路线 C（候选） |
|---|---|---|
| 估计对象 | 漂移幅度（标量） | **目标域的类别条件信任结构本身** |
| 动作空间 | 三候选择一（离散） | **类别 × 模型块的连续权重** |
| 源域角色 | "偏离即报警"的基准 | 各类各模型可靠性的**先验** |

### 3.3 必须保留的一个区分（否则路线 C 没有输入）

目标域上唯一可得的原材料**就是**基模型的预测与概率结构；任何无标签方法都只能从这里取信息。
**分歧结构本身不是错的对象**——错的是把它压成标量、并当作漂移幅度来用。
这一条要写进路线 C 协议，避免把"不用 UDS"误读成"不用目标侧预测结构"。

### 3.4 目标线与工程关系

- **对手是 always-RF 的 regret 0.0203**，不是路线 B 的宽松线（≈ RF − 0.005）。要主张"更高效"必须压过它；
  参考：always-RF 最差环境 0.0318。
- 路线 C ≈ **路线 B + 类别条件分辨率 + transductive 目标信号** → **共用大部分实现**，
  是同一套机器的两个配置，不是两条独立工程。
- 路线 C 使用目标域无标签数据 → **transductive**，按协议 §7 必须单列，不得与 source-only 基线混报。

## 4. 两个关键风险与建议的预注册诊断（**最希望 Sol 回应的部分**）

### 4.1 风险一：伪标签分层偏置

M2 的 C 级用**目标标签**做时间块交叉拟合，能看到**真实**的逐类可靠性。无标签版本只能按**预测类别**分层，
而分层在模型出错处污染最重——漂移下正是错得最多的时候（OOD macro-F1 ≈ 0.63–0.69）。
估出的类别条件结构因此带有**依赖漂移强度的偏置**。

### 4.2 风险二：相关错误盲区（更致命）

分歧只是可靠性的代理，且有一个已知失效模式：**当全体基模型以同一种方式出错时，分歧低、准确率也低**
——分歧驱动的权重会**自信地错**。而"互补性坍缩"恰恰是本项目在 OOD 下反复观察到的现象。

### 4.3 建议的开发期诊断（自采数据，有标签，允许）

检验"由分歧导出的逐类可靠性"与"真实逐类可靠性"的一致程度，**并预先写明不通过的判据**；
不通过就停，不硬做。

### 4.4 建议的前置反事实检验（M4 候选，用独立线自己的手法）

**固定输入、只换关系、量恢复**——把"风险/加权关系"本身做一次反事实：允许在目标域内用标签重拟合
该关系，量能拿回多少 regret。三种读法预先写死：

```
大部分 regret 可拿回 → UDS 不是"弱代理"而是结构性错配（与元层同病）→ 路线 C 有戏
几乎拿不回          → 信息不在这些观测量里 → 路线 C 不值得做，止损
中间                → 按恢复比例决定投入规模
```

**这一步在写任何路线 C 实现之前就能定生死**，成本远低于做完整方法。它不碰主线，
适合作为独立线的下一个冻结协议（照 M1–M3 规格：先冻结、写判否条件、允许否定结果）。

## 5. 治理边界（不可协商，主线侧由 Fable 5 把关）

1. **路线 C 是事后方法**——它在 G1 失败与 M2 结果**之后**产生。合法，但必须：先冻协议后跑；
   在协议与论文中如实声明产生时点；**报告在这 6 个自采环境上一共试过几个方法**（多重性诚实）。
2. **路线 B 必须做完并报告。** 它是协议 §17.3 的预注册承诺，不能因为出现更漂亮的东西而跳过——
   那正是纪律崩塌的典型方式。路线 B 作锚，路线 C 作显式标注的扩展。
3. **确证设计（关键，且协议已替我们留好）**：6 个自采环境已被路线 A/B 用过，在同一批环境上评第三个方法
   有明显的适应性过拟合问题。正确做法是**自采开发 + UNSW 一次性确证**——而 §16.4 检验 2 本就预注册了
   "自采数据上确定的方法是否无需重新设计即可工作（报 selection regret）"，
   **这是现成的、尚未被方法评估污染的留出集**（P2 只做了 gate 与最小 LORO）。
4. **路线 C 是 transductive** → §7 单列。
5. **本讨论解释 G1，不重开 G1。** 判定书不因事后有更好的解释而改判；解释进 Discussion
   （"我们预注册的代理失败了，而独立机制工作解释了它为何必然失败"）。
   若用新解释追认路线 A"其实差一点就行"，即为越界。

也不授权运行。任何实现或数值检查都必须等可行性审阅完成、独立协议与判否条件冻结之后进行。

### 9.1 已知事实与尚待验证的假设

**【已知事实】**

1. 主线 Route A 与 Route B 均未通过各自冻结门，原判定不重开。
2. 独立线 M5-T 的类别条件时间表示 `PT-C` 将 selection regret 降至 `0.010266`，相对 M4-P
   增量降低 `0.002375`，且 4/6 环境改善；但总体只恢复 G1 regret 的 `58.43% < 80%`，
   因而冻结判定为 `TEMPORAL_INCREMENT_NOT_SUFFICIENT_STOP_ROUTE_C`。原 Route C 不再实现，
   UNSW 也未因该路线而打开。
3. M5-T 使用 `source_file`/捕获序列边界计算的是**基模型输出**的切换、概率、熵、置信度和分歧
   episode，并把各序列统计汇总到任务关系；它没有检验“先用原始流量行为显式形成匿名设备表示，
   再用该表示估计类别并条件化模型权重”的方法。因此 M5-T 的止损结论覆盖原 Route C，
   不自动覆盖本节候选，但也不构成本候选可行的正证据。

**【待验证假设】**

同一类物理设备在不同环境中可能保留足够稳定的、独立于基模型输出的行为结构。例如摄像头可能呈现
较高持续流量或占空比，插座可能呈现较长空闲与短促 burst；周期性、上下行比例、包长分布、
burst/idle 时长等也可能提供软类别证据。这里的“可能”是待证假设，不能在协议冻结前写成事实；
还必须区分“同一物理设备跨环境重现”与“同类但未见过的新设备”两种不同泛化任务。

### 9.2 候选机制（概念稿，不是冻结实现）

候选链条如下：

```
新环境无标签流量
  -> 按物理设备形成匿名组 g
  -> 从组内时序提取原始流量行为表示 b_g
  -> 用历史有标签环境学习软类别证据 q(c | b_g)
  -> 用历史环境学习类别×基模型可靠性 R(m, c)
  -> trust(m, g) = sum_c q(c | b_g) * R(m, c)
  -> 以设备组为单位条件化基模型权重并融合预测
```

候选行为表示只考虑部署时可从无标签流量获得的量，如活跃占比、持续性、周期性、上下行比例、
包长/流量分布以及 burst/idle 分布。`R(m,c)` 及行为到类别的映射只能从历史有标签环境学习；
目标环境的真实类别和预测正确性均不得进入估计。`trust` 公式目前只表达机制直觉，归一化、收缩、
拒识与最终融合方式都应在正式协议中先行固定，不能看结果后选择。

这一路径相对原 Route C 多出了一条**独立于模型输出的原始流量行为证据**。若多个基模型在新环境中
共同犯错，单看预测波动可能没有可辨信号；设备行为原型理论上可能提供另一观察轴。但若行为原型本身
跨环境不稳、设备组不可部署地恢复，或其类别证据只是数据集身份捷径，则该路径同样应被否定。

### 9.3 身份、泄漏与比较边界

1. 本候选是 Route A/B 和 M5-T 判定之后提出的**新独立路线**，不是原 Route C 的修改版，
   不修补 CPD，不恢复贡献 2，也不改变 E2、G1、Route B 或 M1--M5 的任何结论。
2. `source_file`、MAC、IP 或其他端点标识至多用于形成匿名设备/捕获边界；其字符串、路径、数值、
   出现顺序和跨环境身份不得作为分类特征。正式协议须说明部署时究竟能取得哪一种分组键，并审计
   地址重分配、NAT、多设备共址与标识漂移。`source_file` 只能是离线数据中的分组代理，不能直接
   冒充可部署传感量。
3. 历史标签可以训练 `q(c | b_g)` 与 `R(m,c)`；目标环境标签只能在最终评分时揭示。
   如同一物理设备跨环境重复出现，必须预先声明这是“有历史设备记录的新环境”场景，或另设严格
   leave-device-out 结果，不能把设备记忆当成类别泛化。
4. 样本量按独立设备/捕获 session 计，不能把同一设备的重叠窗口当作独立重复。划分、调参、
   置信区间和判定门均须尊重设备与 session 簇。
5. 最小比较至少包括三条预先固定的臂：①行为表示单独识别；②原始 RF / Stacking 基线；
   ③行为条件化元模型融合。这样才能区分“行为本身已完成识别”和“行为确实改善了元模型权重”。
   always-RF 仍是方法收益的硬参照；建议同时报告未知/低置信设备拒识，不能强迫所有设备进入
   已知类别后再宣称成功。
6. 在 Opus 完成可行性审阅、数据身份审计和新协议冻结之前，**不得实现、试跑、打开 UNSW 或查看
   任何为本候选定制的结果**。本节也不得被复制进主线执行计划或 registry，是否与主线发生接口
   留待后续单独决策。

### 9.4 明日请 Fable 5 / Opus 优先裁定的问题

1. 该问题是否具有足够清晰的方法贡献与可证伪机制，还是仅为常规流量聚合加一个分类器？
2. 在真实部署假设下，MAC/IP/端点键是否足以形成物理设备组？离线 `source_file` 代理与部署键之间
   需要什么证据才能建立合法对应？
3. 六个现有环境里究竟是同一批物理设备反复出现、部分重叠，还是同类的新设备？当前数据能否支持
   分别回答“历史设备跨环境”与“未知设备实例”两个问题？
4. 每个类别有多少真正独立的设备和 session？在去除窗口伪重复后，样本量是否足以学习行为原型、

5. 若值得继续，正式协议是否应固定：严格 LOEO、必要的 leave-device-out 压力测试、行为-only / RF

### 9.5 两数据集之间的未知设备验证候选

**【适用性判断】** 自采数据与 UNSW 单独看都主要是同一批物理设备跨轮次/日期重复，因而各自只能
直接支持“历史已见设备进入新环境”的验证；但两套数据中的物理设备互不重合。若把两边共有标签
预先对齐到粗粒度功能类型，跨数据集训练与测试可以形成当前最接近“未知物理设备实例”的检查：

```
UNSW 的 camera / switch 设备 -> 训练 -> 自采 Camera / Socket（从未见物理设备）
自采 Camera / Socket          -> 训练 -> UNSW camera / switch（从未见物理设备）
```

该设计允许检验“从一批摄像头/插座学到的设备级行为结构，能否迁移到另一测试床中从未见过的
物理设备”，但它只对应**粗粒度类型迁移**，不对应 Dropcam、某型号插座等精确设备身份迁移，
也不自动证明原五类任务的 selection regret 已被解决。

**【运行前必须冻结的任务边界】**

1. 标签交集先行固定。例如自采 `Camera -> camera`、`Socket -> switch/socket`，UNSW 仅纳入映射表中
   `category=camera` 与 `category=switch` 的设备；Belkin Motion 等传感器不得因名称含 Wemo 而混入
   switch。不得根据可分性再合并、拆分或删除设备。
2. 两个方向必须分别报告，不能只保留有利方向。二者证据强度不对称：自采侧每种类型只有固定设备，
   因而“自采 -> UNSW”实质是单实例原型外推；UNSW 完整映射虽有多台摄像头/开关，当前 M3 四日
   固定十类中实际只有 3 台摄像头与 1 台开关，设备级有效样本仍小。公开 20 日增加 session，
   不会自动增加物理设备数。
3. 分组标识仍只作匿名边界。训练、归一化、调参、阈值和 `R(m,c)` 全部只能使用源数据集；
   目标数据集的标签仅在最终一次评分时揭示。统计单位和加权单位是物理设备，不能让 Dropcam 的
   大量窗口压过低流量插座，也不能把日期或窗口冒充新设备。
4. 自采数据是 802.11 侧观测，UNSW 是网关 Ethernet 侧观测。跨数据集表示只能使用两边可得且
   语义一致的高层行为量，如固定曝光时长下的活跃率、burst/idle、包长、包率和可对齐的上下行量；
   802.11 专属字段不得进入。方向定义、静默窗口、捕获缺口和曝光时长必须统一，否则模型可能只在
   识别采集系统。官方 UNSW 秒级 CSV 不足以构造精细时间行为，必须基于 pcap 派生时间轴。
5. 观测时长必须匹配或做预冻结的多时长敏感性，不能用“UNSW 全天、自拍短 session”的时长差
   作为类别捷径。应同时做数据集身份可预测性审计；跨数据集失败也不能直接归因于设备行为无效，
   因为物理设备变化、测试床变化和链路层变化在该设计中同时发生。

**【两级判定必须分开】**

1. **行为构念层**：只评估 `q(type | b_g)` 的跨数据集 camera-vs-switch/socket 识别。这一级若成功，
   只能说明行为原型具有未知设备迁移信号。
2. **元融合价值层**：在相同的跨数据集、目标无标签设置下，比较行为-only、未条件化基模型/融合、
   行为条件融合。只有第三臂在目标物理设备上稳定优于前两臂，才能说明行为证据确实帮助了元模型权重；
   若只有行为-only 成功，则得到的是新的类型分类器，而不是元失配修正方案。

由于两边原始标签空间分别是自采五类与 UNSW 设备身份类，完整跨数据集元融合不能直接复用原五类
与十类输出；必须另行冻结共同类型任务、公共特征空间和同一组基模型。是否只有 camera/socket 两类
仍具足够方法价值、是否至少加入第三个可严格对齐的类型，以及 UNSW 在已经承担 M3 后应作为开发集
还是次级验证集，均交由 Fable 5 / Opus 在任何实验前裁定。

### 10.2 §9.4 逐条裁定

- **Q3**：自采六环境是**同一批 5 台物理设备**的重采。"历史已见设备进新环境"= 自采数据的全部内容；
  "未知设备实例"在自采数据上**不是难，是不可能**（没有第二台摄像头）。UNSW 单独看同理。
  → §9.5 的判断正确：**跨数据集是唯一可能触及"未知设备"的路径**。
- **Q4**：设备级有效样本量 **1–8，多数 1–3**；自采上 **leave-device-out 在定义上无法执行**
  （抽掉唯一那台设备即抽掉整个类别）。因此"设备行为原型可迁移"这一核心主张
  **在现有数据上无法给出可信的不确定性**。
- **Q1**：有可证伪的核，但**不是 §9.2 现在写的那个核**。`b_g`（活跃占比、周期性、burst/idle、
  包长分布）与基模型吃的是**同一类信息源**，只是聚合粒度不同；"独立于模型输出"在字面上成立、
  在信息意义上不成立。真正新的成分只有**聚合粒度与曝光时长**（基模型按 10s 窗口判，`b_g` 按整段
  会话判）。故主假设应改写为：**跨环境漂移下，会话/设备组级聚合的证据是否比逐窗口分类更稳？**
  这是正经、可证伪、有价值的问题，但它属于**另一项贡献**（聚合尺度影响漂移鲁棒性），
  不是"修正元决策失配"。三臂设计能检测出坍缩（保留），但主假设措辞须改，否则易被质疑
  "为何不直接用那个分类器"。
- **Q2**：MAC 分组在部署上可信（IoT MAC 通常稳定；UNSW 本身按 MAC 标注）。但两处必须写进协议：
  ① **两数据集的标签本身即按 MAC/设备确定**，"按 MAC 分组再判类别"在现有数据上接近自指；
  ② 自采的 `source_file` **等于设备身份**（1 文件 = 1 设备 × 1 轮），用它作分组代理等于把 oracle
  划分交给方法，必须显式审计而非默认等价。
- **Q5**：按上述结论，**不建议作为"方法贡献"路线**。若仍要做，降格为**有界诊断实验**并在协议中
  预先声明"本设计无法支撑方法主张"：三臂结构保留；自采上严格 LOEO 并**明确写明 leave-device-out
  不可执行（n=1/类）**；每张表标注设备级 n；未知设备拒识保留。

### 10.3 §9.5 跨数据集部分裁定

- **camera/socket 两类不足**以支撑方法贡献（目标侧 n=1，属存在性探针）。
- **可对齐的第三类型**现实上是：camera（自采 1 / UNSW 8）、**light（自采 2 / UNSW 1）**、
  sensor（自采 1 / UNSW 4）、switch-socket（自采 1 / UNSW 3）。light 是自采侧唯一有两台设备的
  类型，却是 UNSW 侧最弱的；sensor 在 UNSW 侧有 4 台但属大杂烩类别，语义对齐可疑。
  → 能凑到 3–4 个粗类型，但**至少一侧恒为 n=1**。
- **UNSW 只能作次级验证、且只跑一次**。理由不是纪律洁癖：UNSW 上已有一个成功且冻结的结果
  （M3 两问全过），是全项目最强正面资产；把它变成第四个方法族的开发场地，等于用最有价值的资产
  去赌一个先验不佳的方向。

### 10.4 总体建议：停止向同一批环境追加方法族

这将是**第四个**方法族（A UDS 选择器 → B 全局加权 → M5-T 类别条件时间 → 设备行为条件）。
前三个都有干净的负结果判定，这本身是资产；到第四个，"最终通过者是否为分叉路径产物"的质疑
将难以回避，且正文必须如实报告多重性，说服力递减。

边际价值判断：M3 的外部复现 + M1/M2 的定位 + E1 的评估方法学发现 + 时间块泄漏量化 +
三个预注册方法族的诚实负结果，**已构成一篇完整自洽的论文，不需要一个跑赢 RF 的方法**。
距 11/9 初稿两个多月，把这些写透的价值高于再赌一次约 20% 的方法成功率。

**若仍想探这个方向**，建议改造为 Q1 裁定中的那个问题（**聚合尺度 vs 漂移鲁棒性**）：
成本低、结论无论正负都可用、且**完全不需要动 UNSW**——它问的不是"未知设备"，
而是"同一设备在不同曝光尺度下的证据稳定性"，纯自采数据即可回答。

### 10.5 一并转达的既有意见（§9 之外）

**M5-T / M4 的外层划分可比性**（在 M5-T A 数值出现前提出，现补记以备将来引用）：
M4 与 M5-T A 的外层为 **leave-one-task-out**，而同一目标环境的 25 个任务**共享同一测试集**，
故留一任务时映射器训练集包含"该测试环境的其余 24 个任务"，其目标窗口正是被评估对象。
对 M4/M5-T 的**否定性**结论无害（口径偏乐观 → 上界更松 → 否定更结实）；但任何**正向**主张
在该口径下与 G1 / Route B 的 LOEO（外层 6×25、内层严格全含 70）**不可同表比较**。
M5-T 已按门停止，故此点当前不影响任何结论；若将来有任何路线要主张"优于 always-RF"，
外层须改用留一目标环境，或在正文明确标注口径不可比并同时给出 LOEO 数值。

### 11.3 最被低估的资产：评估口径证据链（四块）

1. **堆叠 OOF 折叠**：随机 K 折 → 分组 OOF 后崩溃**加深**（旗舰 −0.0662→−0.1057；
   `loro_R2_R3_to_R4` −0.0042→−0.2225；joint −0.0012→−0.1037；jitter ≈−0.005→≈−0.08）；
   网格 \|S\|=2 −0.039→−0.093、\|S\|=3 −0.034→−0.054；**\|S\|=1 时间块无加深**（−0.076→−0.070）
   → 加深特异于**跨轮分组 OOF**，非"诚实 OOF"的普遍代价。此对照是让论断精确的关键。
2. **随机 IID 窗口划分**：`random − time_block` 差 R6 **+0.155~+0.206**（时间块下 R6 的"IID"
   仅 ≈0.67 vs 随机 ≈0.87）、R4 +0.052~+0.068、R7 +0.031~+0.043、R2/R3/R5 ±0.018 内
   → 抬高幅度**依环境而变、最大约 0.2**，且只用随机划分完全看不见。
3. **种子噪声尺度**：真 5 种子 std 0.0163 / 0.0102 / 0.0110；多数架构差异落在 1 std 内。
   附带陷阱：两个模型的行是脚本复制的单种子参照，std ≡ 0，naive 聚合会得出"极其稳定"的错误结论。
4. **最罕见的一块——口径伪造了机制证据**：DV 换成历史随机 OOF（A 臂）时 CPD 增量
   **ΔR² +0.267 / +0.482**；诚实分组 OOF 下仅 **+0.007 / +0.075** 且样本外变差。
   即：不改 OOF 构造就会"证实"一个条件检验下不成立的机制，并带着漂亮效应量写进论文。
   关于泄漏的文献多止于精度虚高，能给出"泄漏顺手制造机制解释"的可复算实例很少见。

**为何被低估**：可迁移（任何自相关窗口上的集成工作）、检查成本极低（各几十行代码却能改变
0.02–0.2 的结论量级）、**不依赖本项目任何方法成功或 CPD/EC-MDM 谁对**、可转成可执行清单、
且有精确对口期刊（TIM）。**边界**：分块 CV 原理已知，新意在领域内量化 + 第 4 块的演示；
泄漏幅度目前仅一个测试床，**应在 UNSW 上复现一次**。

### 11.4 用户提出的新候选设定：引入少量目标标签（待冻结协议，未授权运行）

问题：主线能否引入**少量目标标签**（或历史同环境标签）以降低难度，从而得到一个可用方法？

**支持它的既有证据（全部来自已落盘产物）**：

**必须写进协议的四条记账要求**：

1. **不救 RQ3/RQ4，不重开任何判定**。RQ3/RQ4 与 §17.1/§17.3 明确是**无目标标签**设定；

2. **标定集与测试集必须时间块隔离**。若随机抽 k 个目标窗口作标定、其余作测试，
   会重新引入本项目刚刚量化过的相邻窗口泄漏——**用我们自己的发现来设计自己的实验**。
3. **生死线是同预算基线，不是无标签方法**。有 n 个标注后，最自然的竞争者是
   "把这 n 条加入 RF 训练集 / 在目标域直接拟合一个小分类器"。**方法必须胜过同预算基线**，
   否则结论只是"标注有用"。这条是 make-or-break，须在通过线里写死。
4. **运行叙事要能自洽**：可辩护的版本是"部署时一次性标定少量窗口，之后系统自治运行"
   （与真实系统的 commissioning 流程一致）；须回答"若运营方知道设备清单，为何还需要分类器"
   （答：非受管网络、rogue/异常设备检测、无注册接入的安全监控）。

**建议的贡献形态**：主结果不是单点 F1，而是**标签效率曲线**（macro-F1 vs 每类标注数
n ∈ {5,10,20,50,100}），即回答"**修好跨环境集成失配需要多少标签**"。这个问题实用、可量化，
且把本项目最大的短板（没有可用方法）转成方法贡献，同时**让 EC-MDM 成为承重结构而非装饰**。

实现成本估计（若批准）：规格 1–2 h、实现 2–3 h、计算 < 1 h（19 参数）、审阅 1 h。

## 12. 20260831 讨论记录：以工业现实主义理解堆叠、门控与止损

**性质**：用户提出的工程经验框架及 Sol 的适用性审阅。本节只用于解释现状和形成未来决策原则；
不修改主线，不重开 CPD、Route A/B/C 或 M4--M6 的判定，也不授权追加方法或实验。是否引用到主线
正文及其身份由 Opus 按 scope 与登记纪律裁定。

### 12.1 总判断

“堆叠理论上不能保证优于最佳基模型，因此工业实践依靠保险、筛选、ROI 止损、特征空间融合和
No-Free-Lunch 心态绕开”这一框架，**对本项目有帮助，但帮助在决策与叙事，不是新的技术解法**。
其中 Best Single 止损和成本收益原则可以直接采用；“民主投票天然防翻车”和“门控彻底绕开权重
错配”则需要修正。

### 12.2 五点逐项映射

1. **堆叠作为保险：合理目标，不是天然保证。** 多模型只有在错误不完全相关、概率不过度失真且
   路由条件稳定时才可能降低尾部风险；共同域偏移会让多个模型一起错，投票甚至可能更自信地错。
   若要主张“保险价值”，必须在任何结果前固定最差环境 macro-F1、最大 regret、尾部损失、模型
   缺失/输出损坏压力测试和额外时延/成本。不能在平均性能失败后，事后把既有结果改写为鲁棒性成功。
   当前项目的分组 OOF 折叠和跨环境退化没有给出“天然保险”证据。
2. **筛选 / Gating：把问题换了位置，没有消灭信用分配。** M2/M3 已表明，若知道真实类别，类别
   条件块权重是高价值的 oracle；但部署门控必须从可观测量判断“当前样本交给哪个专家”。因此核心
   问题变成 `q(c|g)` 或等价路由信号能否在无目标标签下跨环境稳定估计。Route B、M5-T 与 M6-DBG
   分别从源内系数、时间关系和设备组行为尝试这一接口，均未过冻结门。门控准确描述了瓶颈，不能
   自动解决瓶颈。
3. **ROI 与 Best Single 止损：最适合直接吸收。** 最佳单模型必须始终是正式比较臂。堆叠只有在
   预冻结指标上改善平均收益、最差环境/尾部风险、单模型失效韧性中的至少一项，且收益覆盖计算、
   维护和延迟成本时才部署；否则直接部署 Best Single 并停止堆叠开发。这个停止决定不是失败包装，
   而是成熟的工程策略。
4. **特征堆叠：可能是新监督方法族，不是当前结果的补丁。** 隐向量比最终概率信息丰富，但也更可能
   编码设备身份、测试床和捕获链路。M6 的 H60 dataset-ID AUC 为 0.9905，已经显示丰富行为表示可被
   数据集身份主导；更高维表示不能自动解决跨域可识别性。现有 RF/ET/HGB 也没有统一的“最后一层
   embedding”。若未来研究 leaf encoding、表示拼接或深度 embedding，必须作为新的、先冻结的
   监督/弱监督方法族，不能在同一结果上事后用于挽救主线或独立线。
5. **No Free Lunch：应接受，但失败原因不能简化为信噪比。** 本项目的退化可能来自错误相关、跨域
   校准失效、测量过程变化、设备实例捷径和目标无标签下的不可识别性。正确结论是复杂集成并非默认
   更好，而不是笼统宣称“该数据集不需要堆叠”。

### 12.3 对本项目可采用的正式原则

```text
默认部署候选 = Best Single

只有当预冻结证据证明：
  (a) 平均性能有足够增益，或
  (b) 最差环境 / 尾部风险有足够改善，或
  (c) 明确故障压力下更稳，
且收益覆盖额外成本，才升级为集成。
否则停止，不事后更换成功定义。
```

这套原则强化两项已经成立的贡献：一是“评估口径能制造虚假的堆叠收益与机制解释”；二是
“oracle recoverability 不等于 observable estimability，更不等于 deployability”。它不恢复 CPD，
也不把 M2/M3 的有目标标签上界改称无标签收益。

### 12.4 唯一较现实的后续接口

若目标仍是把类别条件结构变成可用系统，当前最现实的接口不是继续无标签特征搜索，而是 §11.4 的
少量目标设备级标签、入网确认或可靠弱标签。它可以为 gating 提供类别锚点，但会把问题改成一次性
commissioning / 弱监督适配；必须与无标签主线分账，并战胜同标签预算的直接微调或小分类器基线。

在 Opus 完成现状裁定前，本节只作为讨论材料。若未来没有新增信息、可识别性假设或独立数据，
则不建议围绕“保险”“门控”或“特征堆叠”继续在现有数据上分叉实验。

### 14.2 【已验证】充足的同环境历史标签使跨环境聚合问题坍缩

数据来源：`results/g0_environment_grid/summary_metrics.csv`（`grid_kind = iid_time_block`，
model = rf）与 `results/route_b/route_b_env_summary.csv`（`mean_f1_rf`）。

| 目标环境 | 跨环境 source-only RF | 本地时间块 RF（同环境历史标签） | Δ |
|---|---:|---:|---:|
| R2 | 0.7702 | 0.9541 | **+0.1839** |
| R3 | 0.6796 | 0.9546 | **+0.2750** |
| R4 | 0.7265 | 0.8756 | **+0.1491** |
| R5 | 0.6441 | 0.9504 | **+0.3063** |
| R6 | 0.6239 | 0.6790 | **+0.0551** |
| R7 | 0.6780 | 0.8451 | **+0.1671** |

**三条含义，其中第二条直接改变通过线设计：**

1. **约 260 窗/类的同环境历史标签，把跨环境部署问题基本解决掉**：+0.19、6/6 环境为正。也就是说

2. **本地重训（0.8765）高于元层修复的有标签天花板（target-CF ≈0.83）**。因此在标签充足时，

   整件事会被读成失败。可辩护的写法是：预先声明主张只在**低 n 区间**成立，并把交叉点 n\* 作为交付物。
3. **R6 是唯一的例外，而且它的例外可被本项目自己的诊断量预测**。`random − time_block` 差
   （§11.3 第 2 块）与本地标注回报呈反向对应：gap 最大的 R6（0.1550）回报最小（+0.0551），

   **这条联动有独立价值**：同一个揭示泄漏的诊断量，同时预测「在这个环境标注本地样本值不值得」。
   它把 §11.3 的评估口径资产从「批评」变成「可用于部署决策的量」。

### 14.3 少量目标标签（few-shot 元层修复）：唯一的「方法 1」候选

支持它的既有证据仍然是 §11.4 那三条（可恢复空间 ≈0.14 已量化；M2 已指认低容量参数化
I = 4 / G = 7 / C = 19 参数；完整 target-CF LR 约 80 参数，容量是 C 级四倍）。§14.2 增加两点：

- **这个实验没有「失败」的结局**。它测的是标签效率曲线，不是一个方法过不过门——无论 C 级适配器
  在哪个区间胜出，都会产出一条可引用的曲线与一个交叉点 n\*。这与 Route A/B/C 的性质根本不同，
  也是它风险最低的原因。
- **它的对手在低 n 区间其实很弱**：n=5–10/类（25–50 窗）加入约 1300–3700 窗的源域训练集，
  对 RF 几乎无影响；而同样 25–50 窗用于估 19 个参数是可行的。低 n 区间是元层修复的天然地盘。

### 14.4 对 §13.4 正式协议的三条追加要求（审阅方，运行前必须满足）

1. **所有臂必须在同一批留出窗口上评估**。§14.2 的 +0.19 是**指示性量级**，不是严格可比数：
   `iid_time_block` 的测试集是目标轮的后段时间块（546–598 窗），而 OOD 任务测试整轮（约 1816 窗）。
   正式协议须对每个目标环境作前段/后段时间块划分，标定预算 n 只从**前段**取，
   跨环境 RF / 原始 Stacking / 校准 soft / 本地重训（预算 n）/ C 级适配器（预算 n）
   **全部在同一后段窗口上评估**。
2. **通过线按预算区间声明**（承 §14.2 第 2 条）：预先写明主张成立的 n 区间，以及在高 n 区间
   预期被本地重训支配这一事实；不得在结果揭示后挑区间。
3. **自采数据的时间跨度不足以支撑「历史标签」的部署叙事**。轮内前后段相隔很短，只能支持
   「入网时一次性标定、随后自治运行」这一叙事，**不能**支持「用一个月前的标签」。要检验真正的
   时间距离，正确的场地是 UNSW 的 20 天跨度（标定第 1 天、测试第 5/10/20 天）。该扩展属于测量而非
   方法选择，但仍须显式 scope 记录，且建议并入 §16.4 检验 1 / UNSW 主实验的编排，不单独消耗
   「UNSW 只打一次方法确证」的额度。

### 14.5 不变的边界

设定变更不恢复任何东西：RQ3/RQ4 与 §17.1/§17.3 是**无目标标签**设定，Route A/B/C 与 M4–M6 的

### 15.1 可以保留的结论

1. **充足同环境标签与少量 commissioning 标签必须分开记账。** 前者回答“本地监督信息的高预算

3. 正式实验的主要输出应是完整标签效率曲线，以及 C 级适配器与直接本地适配之间是否存在交叉预算

### 15.2 “实验总有产物”不等于“方法不会失败”

标签效率曲线作为**测量产物**几乎总能生成；C 级适配器作为**方法主张**则必须允许失败。正式协议
至少应区分以下事实分支，具体名称和数值门由 Opus 在运行前冻结：

- C 级适配器在预声明低预算区间稳定胜过全部同预算基线：方法优势成立；
- 标签有用，但 C 级适配器不优于直接 RF 更新或目标域小分类器：只能得到标签价值曲线，方法不成立；
- 低预算增益本身跨环境不稳定：方法与标签效率主张均须相应降格。

如果 C 级曲线在预设预算范围内从未超过同预算基线，则 `n*` 应报告为“在观测范围内不存在”或
“右删失”，不得为了交付一个交叉点而扩大预算、删环境或改变基线。因此 §14.3 的“没有失败结局”
只能理解为测量问题总有可报告结果，不能进入方法协议的通过逻辑。

### 15.3 低预算对手强弱目前仍是待检验假设

“将每类 5--10 个目标窗口加入大量源域样本后，RF 几乎不受影响”尚未由已落盘结果验证。它取决于
目标样本权重、重采样、类别平衡、超参数和源/目标混合方式；同样，25--50 个标注窗口能否稳定估计
19 个 C 级参数，也不能只由参数计数推出。

正式协议必须在任何结果可见前冻结：

1. source + target RF 如何合并样本、设置样本权重和处理类别平衡；
2. 目标域低容量分类器、C 级适配器和其它臂使用完全相同的标注预算；
3. 正则、早停、超参数选择和并列打破不得读取后段测试标签；
4. 各臂在相同 source task、相同前段标定样本及相同后段测试窗口上评分。

在这些条件满足之前，低 `n` 是 C 级适配器的**合理候选优势区间**，不是已经确认的天然胜区。

### 15.4 R6 “预测标注回报”存在代数耦合

记目标环境 `e` 上：

```text

payoff_e = F1_timeblock,e - F1_source,e
```

两个量共享 `F1_timeblock,e`，且符号相反。因此即使三个最大 gap 与三个最小 payoff 的顺序吻合，
负向对应也有一部分由指标构造机械产生。这与项目此前对 `CPD_y` 和 recall 共享误差质量的代数耦合
审计属于同类问题。

此外，计算 `gap_e` 本身需要目标环境标签，不能直接作为无标签部署前的标注 ROI 信号。§14.2 第 3 条
最多保留为**n=6、共享项耦合下的描述性观察**，不得写成独立预测关系或已验证的部署决策量。若未来
要检验标注回报预测，预测量必须与 payoff 不共享结果项，并在独立环境上先冻结后验证。

### 15.5 `+0.1894` 与高预算支配关系的引用边界

§14.2 已正确注明：本地 `iid_time_block` RF 与跨环境 source-only RF 当前并非在同一批测试窗口上

其中 **26 个（28%）仅在描述两个边际分布的不同分位数**。再加同族分位数是纯冗余，
边际价值已很低。**裁定：数量不是瓶颈，不批准以"补特征数"为目标的扩充。**

### 17.3 唯一带来新信息的方向：跨窗口时间尺度

上表最关键的一行：**10 个特征往 10s 窗口内看（`subwin_*` + `active_subwin_count`），
0 个特征往窗口外看。** 全 94 维中没有任何跨窗口量——无占空比、无 >10s 尺度 burst 间隔、
无周期性/自相关、无距上次活动时长、无窗口间差分。

三条已落盘证据同向：

1. **近乎退化窗口**（`features_raw_all_w10.csv`，11303×102，`min_packets_per_window = 2`）：
   全体 **12.7%** 窗口 <10 包、2.7% <5 包；逐类极不均——Sensor **29.2%**、Light_T1 **20.5%**、
   Light_XM 8.9%、Camera 4.3%、Socket 0.7%（中位包数 20/21/24/36/43）。
   在 2–9 包的窗口上，12 个 interarrival 特征与 burst 特征基本是噪声。
   而 Sensor 与 Light_T1 恰是跨环境崩溃最重的两类（抽查 `g0_R3_to_R2` RF 逐类 F1：
   Camera 0.920 / Socket 1.000 / Light_XM 0.706 / Light_T1 **0.158** / Sensor **0.023**；
   仅一个任务，属**待检验的对应关系，非已证因果**）。
2. M6-DBG 行为-only 跨数据集 session macro-F1 掉到 0.27–0.33；
3. 本文档 §10 裁定已指出，设备行为条件候选真正新增的成分只有**聚合粒度与曝光时长**。

**关键实现约束（决定这条路是否可行）**：补该方向**不必改窗口**。保持 10s 窗口与现有 94 列
一字不动，**只额外计算跨窗口特征并加成新列**。改窗口长度会作废全部落盘证据
（162 个 G0 任务、E1、E1-G0-GRID、E2、G1、Route B、D8、S1，以及**整条独立线** M1–M6
——后者全部读 10s/94 维的 G0 产物）；加列不会。**10s 与 94 列作为主设定无条件保留。**

### 17.4 协议/载荷族：物理不可得，不是努力问题

94 维中无任何端口、协议号、DNS、TLS、IP 层特征——全为链路层 + 尺寸/时序。而 IoT 指纹文献
主力恰为该族（含 UNSW 数据集作者本人的工作，使用端口/域名/cipher suite）。现场探测：

```text
自采 dataset/camera/round2_normal/camera_r2.pcapng
  radiotap:wlan_radio:wlan:data  2644 | radiotap:wlan_radio:wlan  356   → WPA2 加密，无 IP 层
UNSW dataset/unsw/pcap/16-09-25.pcap
  eth:ethertype:ip:tcp 1664 | ip:tcp:tls 720 | arp 434 | ip:icmp 221
  | ip:udp:ssdp 172 | ip:udp:dns 68 …                                   → 明文，全族可提
```

**裁定**：自采侧该族**结构性不可得**，因此不得用于跨数据集对比；UNSW 单侧提取属 §16.4
明写"不做"的范围，需另行 scope 决定。建议把它写成论文的**设定声明**而非疏漏：
"加密无线流量下仅凭尺寸/时序可达到什么"是一个明确且有价值的设定。

**同时更正 §14 之后一处推得过强的表述**：先前以"UNSW 61 通用特征、10–14 类达 0.816–0.867
高于自采跨环境 0.687"推断"RSSI 非必需"，该推断偏强——两设定差别不止特征集（自采多一个
无线传播干扰变量，且**少**明文载荷整族信息），不可直接比。RSSI 去留必须由实际消融数字裁定。
