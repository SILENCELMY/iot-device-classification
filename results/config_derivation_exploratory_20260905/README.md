## 主结果

UNSW outer `16-09-23 → 16-10-12`（inner `23→30`）；CIC outer `1102Idle → 1108Active`
（inner `1102Idle→1103Active`）。配置只用 inner 导出，outer 完全 held-out。2 seed。

**两半都属于本方法**——平滑是「位移下复杂度不买账」这一主张在时间轴上的推论，
与 always-RF 同源，不是外部基线；且闸门的定义里就含平滑（「相对已平滑的在位者有增益才动手」），
没有平滑当在位者就退回 v2 的 +0.0243，两者在设计上不可分。

**但仍必须拆开报，因为两半的代价不同**：平滑不要标签、不要 inner 环境、不要逐类对机制，
任何人立刻能用；定点修要 ≥2 个有标签环境 + 逐类对搜 (模型, 时长) + 闸门。
读者要据此决定「只做便宜那半够不够」，合成一个数字他判断不了。

## 两层，各治一种失效模式

- `smooth_control.py` —— 全局同流因果时间平滑（基模型多分类概率在同一流连续 k 窗上平均，
  k 在 inner 上选）。治**方差**。零拟合参数、零容量。
- `cfg_v3.py` —— 逐类对 (模型, 时长) 配置，**只在 inner 上打得赢已平滑的在位者 + margin 0.01
  时才覆盖**。治**偏差**。

**闸门是关键**：`cfg_joint.py`（绝对闸门 AUC≥0.95）在 44/45 对上动手，UNSW 只得 +0.0243，
因为在 8 个容易类上每次都赔一点；改成相对在位者后只动 1–2 对，变 +0.0723（2.5×）。

逐类 F1（UNSW seed42）显示两者互斥：

```
                  base     平滑k3   平滑k10   v2全覆盖
BelkinWemoSwitch  0.4678   0.5285   0.3189   0.8936
BelkinWemoMotion  0.6343   0.7421   0.7090   0.8751
其余 8 类          —        0.94–1.00        全部低于平滑
```

平滑在最难的类上不但没用，k=10 时反而压到 0.3189（低于不平滑）——
**平滑降方差、固化偏差**：基模型系统性判反的对，平均越多越确定地错。

## 适用条件（可在动手前用 inner 判定）

**错误质量集中在少数类对上，且这些对在 inner 上可修、跨环境稳定。**

## 关键诊断

- **`pair_auc` 用 LR、部署用树**，逐类对 AUC 差 0.15–0.86 且方向相反
  （GlobeLamp LR 0.9997 / xgb 0.1431；Netatmo LR 0.4194 / RF 0.9934；Belkin LR 0.6917 / RF 0.5389）。
  机制：树的分裂点钉在源域取值上，目标域落到区间外被路由到错误叶子。
  **此前所有基于 `pair_auc` 的分型结论需按此重算。** → `hard_pair_rescue.py`
- **观测时长**：Belkin 0.6917 @k=1 → 1.0000 @k=10，三个迁移任务一致。→ `hard_pair_rescue.py`
- **top-2 覆盖天花板**：UNSW +7.38 / +9.98 / +11.63 点，CIC +11.29 点。→ `top2_ceiling.py`
- **CIC 机制开火但不兑现**：L1 3/7 正值族（UNSW 0/7），过下限的 26 对 100% 含 AMCREST，
  但 Δmacro ≈ 0——开火的全是本来就判对的。→ `cic_probe_gate.py`
- **捕获内时间留出不足以证明设备身份**：同域时间块 AUC 1.0000，换一次抓包跨域 0.15 → 0.92。
  对自采所有 in-domain 参考值同样适用。→ `cic_invert.py`

## 与项目主张的关系

「环境位移下复杂度不买账」的第四、第五次验证：
④ 零参数的平滑打赢了我们建过的全部复杂机制（stacking / 元模型 / 特征掩码 / 容量搜索）；
⑤ 逐类对选模型时程序几乎从不选最高容量的——v2 的 44 对里 xgboost 只中 1 次，v3 的 3 对里 0 次。
修复动作是**退到更简单的模型**（LR），不是更复杂的。

# 续（同夜后段）：闸门判据的两次修正，与 CIC 的最终归因

| UNSW（10 类）| 0.8379 | 0.9054 | 0.9802 | +0.0675  | **+0.0748** | 3–5 / 33 | 2 |

| 版本 | 闸门判据 | UNSW | CIC |
|---|---|---|---|
| v2 `cfg_joint` | 绝对 AUC ≥ 0.95（几乎全过） | +0.0243 | — |
| v3 `cfg_v3` | 相对在位者的 AUC，全体窗口 | +0.0702（5 seed） | −0.0008（5 seed） |
| v4 `cfg_v4` | 同上 + top-K 覆盖（K 在 inner 选） | +0.0775 | +0.0015 |

```
UNSW  BelkinMotion|BelkinSwitch   可判决区 3544   在位者 0.5133 → 配置 0.9763  (+0.4630)
CIC   GlobeLamp|Gosund039AAF      可判决区  220   在位者 0.0000 → 配置 0.8909  (+0.8909)

```

## 为什么闸门要改两次

**v3/v4 的判据测错了总体。** 同一个类对，在「两类的全部窗口」上逐类对 AUC = 1.0000，
在「这两类争 top-2 的窗口」上是 0.03——全体上的高分被大量轻松判对的窗口撑着，
恰好把决策真正发生的那一小块掩盖掉。而且 AUC 对切点免疫，两个毛病叠在一起。
v5 改成**可判决区上的准确率**，一次解决两个：换对了总体，且准确率按实际判决规则算。

诊断能力的提升是实的：CIC 过闸从 12/350 变成 7/74，且每一对的病看得清清楚楚
（在位者准确率 0.0000 这种，在 AUC 口径下完全看不见）。

## CIC 的最终归因：五个假设，四个证伪

| # | 假设 | 结果 |
|---|---|---|
| ① | inner 与 outer 位移不同型 | **证伪**：同型化 −0.0045 → −0.0048 |
| ② | top-2 覆盖够不着 | **证伪**：可及率 +25 点（42.0%→66.9%），收益 +0.0026 |
| ③ | 切点 | 测试被子集类别不平衡混杂，不可读；被 v5 的准确率判据绕过 |
| ④ | 闸门测错总体 | **一半成立**：诊断大幅改善，但端到端仍 +0.0017 |
| ⑤ | **逐类对修复在 CIC 上不跨日迁移** | **剩下的解释**，证据最强 |

⑤ 的证据：v5 在 inner 上把 `GlobeLamp|Gosund039AAF` 从 0.0000 修到 0.8909、
`GlobeLamp|Gosund032979` 从 0.1098 修到 0.9294，**六对合计可判决区约 1000 窗**，
到 outer（1108Active）只兑现 +0.0019。**修得出来、迁不过去。**
与更早的观察一致：Gosund 对的跨域 AUC 逐日 0.15 / 0.69 / 0.92。

**故适用条件应写成：逐类对关系需跨环境稳定——而这可用两个 inner 环境对交叉检验，
不稳就不动手。** UNSW 满足，CIC 不满足。

## 补测的两个缺口

- **③ 逐日漂移并非全不可修**：固定源 1102Idle 后，`Gosund032979|1ACEE1` 用 **LR + k=5
  在 1103Active 与 1108Active 上都是 1.0000**。此前把它判为「逐日漂移不可回收」，
  一半是测量方式造成的假象（极性测试同时换了源和目标）。
  另一对 `Gosund10ACD8|147FF9` 确实修不动（≤0.36）。闸门在 inner 上就能看出后者，不会误开火。
- **v3 逐类 F1 实测**（此前从 macro 反推）：`BelkinWemoSwitch` 0.4678→0.5285→**0.9380**、
  `BelkinWemoMotion` 0.6343→0.7421→**0.9422**，**其余 8 类与平滑逐位持平**。
