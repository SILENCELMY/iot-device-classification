## 1. 旧结论是什么

> CPD（混淆模式漂移）越高，Stacking 增益越低：Pearson r = -0.630 (p = 0.038)，统计显著。
> （`CONTROLLED_CPD_MECHANISM_VALIDATION_FINAL.md`，11 个训练-测试场景）

这是此前"CPD 可预测集成失效"机制主张的主证据。

## 2. 审计发现了什么

**口径问题**：三个历史 CPD 数值（0.8397 / 0.801 / 0.1521）来自**三种不同基准**，量级差异不是漂移大小差异而是"不同问题的答案"（IID 环境间差异 vs OOD 相对 IID 参照的漂移）。已统一为 `cpd_core.py` 唯一实现，三个值逐位复现并归因（`CPD_DEFINITIONS.md`）。

**统计问题**（`results/p0_audit/R630_SENSITIVITY_CONCLUSION.md`）：

| 检验 | 结果 |
|---|---|
| Spearman 秩相关 | ρ=-0.50, p=0.117，**不显著**（原报告并列报过但结论层忽略） |
| Leave-one-task-out | 仅 3/11 次仍 p<0.05；剔除 `loro_R2_R4_to_R3` 后 r=-0.37 (p=0.30) |
| 环境聚类 bootstrap | 95% CI [-0.97, -0.08]，极宽 |
| 反例 | 两个 CPD 近乎相同的任务（0.84 vs 0.80），增益差 **25 倍** |

**结论**：方向（负）在环境层面稳健，但幅度与显著性由单个任务支配。已按预注册规则**降为探索性结果**，两处历史报告已加注。

**管道问题**：Stacking 的 OOF 用随机分折，相邻 10 秒窗口被拆开 → 概率偏乐观（已修复：按轮次分组 + 时间块，历史实现保留为对照臂；RF 与对照臂逐位复现旧值，修复未破坏可比性）。

## 3. 修正方案（预注册，不改协议）

- **E1**（9/7 前）：两臂对比 A=随机 OOF / B=分组 OOF。原假设是"B 臂可能使旗舰崩溃值（-0.0693）消失，从而 r=-0.630 失去唯一支撑点"。今日预验证结果**与该假设相反**：B 臂使该任务 stacking macro-F1 0.5455→**0.4907**，gain 从 -0.0693 深化到 **-0.1241**（约 1.8 倍）。即修正 OOF 后崩溃不仅没消失，反而更严重——`r=-0.630` 的支撑点被加强，但这同时说明历史 Stacking 结果整体偏乐观。（注：该任务仅 2 个源轮次，GroupKFold 退化为 2 折，元特征噪声大于历史 5 折，正式 E1 前需确认口径。）
- **E2**（9/12 前）：分层回归区分"CPD 是机制还是目标环境难度的描述"。
- **G1**（9/14，路线决策门）：嵌套 LOEO 评价，不延期解释。
