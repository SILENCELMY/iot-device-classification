## 1. Research Question

环境变化会改变 IoT 设备分类器的混淆结构，破坏基模型之间原有的互补性，使在源域训练的 Stacking 元学习器在目标域失配。本文研究：**如何诊断这种失配，并在无目标标签条件下规避高风险的集成决策。**

对应五个可检验问题：

| ID | 问题 |
|---|---|
| RQ1 | 环境变化是否造成混淆结构漂移（而非仅性能下降）？ |
| RQ2 | 该漂移为何损害 Stacking？ |
| RQ3 | 无标签代理能否在部署前预警？ |
| RQ4 | 基于该代理的方法能否降低部署风险？ |
| RQ5 | 结论能否在第二个数据集上成立？ |

**优先级**：RQ1/RQ2 口径可信 > RQ4 方法有效 > RQ3 代理解释 > RQ5 外部验证 > 深度架构扩展 > 新特征。

## 4. Definitions

### 4.1 三个指标（唯一合法命名）

| 名称 | 需要目标环境真实标签 | 可用于部署前 | 依赖性质 | Transductive |
|---|---|---|---|---|
| `CPD_y` | **是** | **否** | performance-dependent（行归一化后每行离对角质量恰为 `1 − recall_i`） | 否 |
| `CPD_dir` | **是** | **否** | 已去除误差幅度，但**不得声称完全独立于性能**（见 4.3） | 否 |
| `UDS` | **否** | **是** | prediction-only（只用模型预测，不用标签） | **是**（若使用整批无标签目标样本） |

### 4.2 数学定义

设混淆矩阵 `C`，行归一化 `C̃_ij = C_ij / Σ_k C_ik`，`Off(C̃)` 为置零对角后的矩阵。

```
CPD_y(C_ref, C_tgt) = || Off(C̃_ref) − Off(C̃_tgt) ||_F
```

`CPD_dir`：对每行 `i`，将离对角向量再按 L1 归一化为 `D_ij = Off(C̃)_ij / Σ_{k≠i} Off(C̃)_ik`（即 `P(ŷ=j | y=i, ŷ≠i)`），然后

```
CPD_dir(C_ref, C_tgt) = || D_ref − D_tgt ||_F
```

`UDS`：对模型对 `(m_a, m_b)`，统计"在 `m_a` 预测为类 `c` 的样本上，`m_b` 的预测分布"，构成分歧矩阵 `G^{ab}`（行归一化）。源域用 OOF 预测、目标域用测试预测，取

```
UDS = mean over (a,b) pairs of || Off(G^{ab}_src) − Off(G^{ab}_tgt) ||_F
```

**`UDS` 的计算不读取任何标签。** 代码审计必须能证明这一点（见第 17 节 G1 条件 5）。

### 4.3 `CPD_dir` 的动机与限制

**动机（必须保留，不得当作可选项砍掉）**：行归一化后每行离对角质量恰好等于 `1 − recall_i`，因此 `CPD_y` 在**代数上**内含误差幅度。用它去预测 ΔF1，相关性高有一部分是代数必然。`CPD_dir` 只保留误分类方向。

**限制**：`CPD_dir` 去除了误差**幅度**，但**没有**去除误差**计数**带来的估计噪声——误差极少的行，方向分布估计方差极大，会系统性抬高高准确率环境的 `CPD_dir`。因此：

- 每行要求最少误分类样本数 `n_err ≥ 20` 才纳入 `CPD_dir` 计算，不足则该行置为缺失并在结果中标注；
- RQ1 必须附**置换/随机标签参照**，给出 `CPD_dir` 在无真实漂移下的零分布。

### 4.4 已废弃的定义

- ~~`cpd_env`（无标签、部署前可算）~~ — **明确废弃**。混淆矩阵按定义依赖真实标签，任何由真实混淆矩阵计算的环境间距离都需要目标环境标签，不能宣称部署前可算。V2 的这一表述是方法学错误。
- ~~`six_env_off_diag_frobenius_rf.csv` 六环境矩阵~~ — **明确废弃**。其 `env_mapping`（`six_env_confusion_similarity.py` 第 33-39 行）把 R2/R3/R4 指向 `single_round_*`（IID 模型）、R5/R6/R7 指向 `position_*`/`jitter_*`（OOD 模型），矩阵不同质。旧文件移入 `legacy/`，并在 `CPD_DEFINITIONS.md` 注明原因。
- ~~"无标签 CPD"这一叫法~~ — 统一改称 `UDS`。

## 8. Data Splitting Rules

1. **外层评估单位 = 完整环境/轮次**，采用 leave-one-environment-out（LOEO）。
2. **内层调参、阈值选择、指标口径选择只能使用外层训练环境**。严禁查看外层留出环境的标签。
3. **禁止 selection-on-test**：不得用外层留出环境的成绩选择最终 CPD 口径 / 代理 / 阈值，再报告同一留出环境的成绩。口径选择在内层完成。
4. **IID 划分**：`single_round` 的随机分层划分（`task_data`，`robust_iot_research.py` 第 912-917 行）会把相邻 10 秒窗口同时放入训练与测试。该结果**只能称为"session 内上界"**，并必须并列报告按 `window_start` 分块的时间划分数值。
5. **环境组合网格（G0）**：对每个目标环境 `e ∈ {R2..R7}`，源环境取 `S ⊆ {R2..R7}\{e}`，`1 ≤ |S| ≤ 3`（每个 `e` 有 25 个组合，共 150 个 OOD 任务），另加 6 个同环境 IID 任务。`|S|=1` 的 30 个有序对构成**同质**的环境×环境拓扑矩阵，替代已废弃的六环境矩阵。
6. **网格的定位**：扩大方法开发与失败模式覆盖、为外层选择器提供内层训练任务、检查源环境数量/距离/类型的趋势。**不用于显著性结论**。
7. **外部验证协议先写后看**：UNSW 的测试协议与判据必须在查看最终结果前写入本文档。

## 9. OOF / LOEO Protocol

### 9.1 源域 OOF（强制修改）

现有 `SimpleStackingClassifier.fit`（`robust_iot_research.py` 第 560 行）使用
`StratifiedKFold(n_splits, shuffle=True, random_state)`，在合并后的训练轮次上**随机分折**，相邻 10 秒窗口被拆到不同折 → OOF 概率偏乐观。

**协议要求**：

- **多源轮次**：按轮次分组交叉验证（`GroupKFold`，group = `round`）；
- **仅单轮时**：按 `window_start` 时间块划分，**不得随机打散相邻窗口**；
- 原实现保留，仅用于 E1 的对照臂。

### 9.2 嵌套 LOEO

```
for 留出环境 e_out in 6 个环境:
    外层训练环境 = 其余 5 个环境
    ├─ 内层：仅在外层训练环境上
    │    · 生成源域 OOF（按轮次分组）
    │    · 计算 UDS
    │    · 学习阈值 / 轻量选择器
    │    · 选择 CPD 口径（如需要）
    │    · 调超参数、做校准
    └─ 外层：在 e_out 上评估一次，不回头调整
```

外层评估**每个环境只做一次**。任何回头修改内层设置后重评的行为必须记入 Change Log。

## 10. Metrics

**主指标（同时报告）**

1. **5-class macro-F1**（沿用历史口径，保证与既有 110 条结果可比）
2. **4-class macro-F1（去除 Socket）** — Socket 在 110 条结果中 96 条 F1 = 1.000，位置漂移与抖动漂移下亦为 1.0；5 类 macro-F1 中有 1/5 是免费的，实际难度接近 4 类
3. **最差类 F1**
4. **Stacking gain** = `F1(stacking) − max F1(base models)`
5. **selection regret** = `F1(该任务事后最优候选) − F1(选择器所选候选)`
6. **运行开销**（训练与推理，IoT 场景评审常问）

**辅助指标**：accuracy。

**每个主结果表必须同时包含**：均值、离散程度、最差环境、计算开销。

## 12. E1 — OOF correction / Stacking robustness

**目的**：判断既有 Stacking 崩溃是否依赖错误的 OOF 划分。这是竞争解释的区分，不是增加实验数量。

**设计**：两臂，除折叠方式外一切相同（同任务、同特征集、同基模型、同超参数、同种子集）。

| 臂 | OOF 折叠方式 |
|---|---|
| A（原始） | `StratifiedKFold(shuffle=True, random_state=42)` |
| B（协议） | `GroupKFold(groups=round)`；单轮任务用 `window_start` 时间块 |

**任务范围**：11 个既有主线任务 + G0 网格中 `|S|≥2` 的任务（`|S|=1` 无法按轮次分组，改用时间块并单独标注）。

**主要观测量**：逐任务 Stacking gain 的 A → B 变化。**重点关注旗舰崩溃值 `loro_R2_R4_to_R3` 的 `−0.0693`。**

**预注册解读规则（不预设哪个结果正确）**：

```
若 B 臂崩溃仍存在（|gain| 保持同量级、方向不变）
    → 现象基础成立，继续按 X2 检验机制
若 B 臂崩溃大幅消失（|gain| 缩小到与其它任务同量级，或方向反转）
    → 必须降低或修改机制性主张：
      · 正文改写为"在特定 OOF 构造下 Stacking 失效"，明确这是实现相关的失效
      · 不得继续把 −0.0693 作为旗舰案例
      · RQ2 的叙事重心转向错误相关性与 meta 权重，不再依赖该单点
两种结果都要如实写入正文或 Discussion，不隐藏
```

## 13. E2 — CPD conditional explanation

**目的**：区分"真正的 CPD 机制"与"目标环境本身更难导致的性能下降"。

**动机**：在 `loro_R2_R4→R3` 中 Sensor 召回从近满降至 18.7%。竞争解释是：R3 的 Sensor 窗口本身异常，任何未见过 R3 的模型都会在 Sensor 上失败，"拓扑变了"只是"Sensor 变得不可识别"的另一种说法。此时 CPD 是对失效的**描述**，不是**机制**。

**设计**：分层回归，因变量 = Stacking gain。

| 模型 | 预测变量 |
|---|---|
| M0 | 逐类 recall 变化向量（对每类：`recall_src_IID − recall_tgt`），以及其 L2 范数与最大值 |
| M1 | M0 + `CPD_y` |
| M2 | M0 + `CPD_dir` |

**观测量**：M1、M2 相对 M0 的增量解释力（增量 R²，或按环境聚类的交叉验证预测误差改善），附效应量与按测试环境聚类的 bootstrap 区间。

**预注册解读规则**：

```
若控制逐类 recall 变化后 CPD 仍有增量解释力
    → CPD 可作为机制性量，但仍不得表述为因果
若增量解释力消失
    → CPD 只能作为描述性刻画
      · 不得写成独立机制
      · 贡献 2（机制证据）降级为"失效模式的结构化描述"
      · 论文主线转向贡献 3（部署方法）
```

**统计纪律**：6 个环境下自由度有限。报告效应量与完整环境结果，**不追求"凑显著"**，不做未校正的多重检验。

## 15. Statistical Analysis

1. **聚类单位 = 测试环境**。正式区间用按测试环境聚类的 bootstrap。
2. **禁止**对高度相关的约 150 个任务做点级 bootstrap 或把 `n` 写成 150 做显著性检验。
3. **禁止**未经校正的多重显著性检验。
4. 主表同时给出**六个目标环境各自的结果**，不只给均值。
5. 相关性同时报告 Pearson、Spearman、95% CI、leave-one-environment-out 敏感性。
6. 模型比较优先采用**配对、按环境聚类**的 bootstrap 区间；样本很少时报效应量与完整环境结果。
7. 混淆矩阵由约 380 个高度自相关的 10 秒窗口估出，其有效精度低于 `n=380` 所示。凡对 CPD 差异做区间估计，须在正文说明这一限制。
8. 由于自采数据只有 3 种漂移类型、6 次采集，**显著性结论必须由第二数据集补强**，不得由自采数据单独支撑普适性主张。

### 16.2 pcap / CSV 硬约束（不得因 CSV 更方便而更改）

**pilot 必须使用 pcap。** 官方 CSV 版仅 4-17 MB/天，但 `TIME` 字段是 **int64 秒级整数**——实测 `16-09-30.csv` 共 673,414 行、跨度 86,398 秒，只有 **84,291 个唯一时间戳**。因此：

- `interarrival_*`、`burst_*`、`subwin_*` 三族时间特征在 CSV 上**全部失效**；
- **不得用 CSV 验证 interarrival / burst / subwindow 类时间特征的可提取性**，否则会得到假阳性的可行性结论；
- CSV 仅可用于设备清点、窗口计数、类别可用性初筛。

1. 许可是否允许论文使用与派生特征发布；
2. **MAC 到设备映射是否完整且跨天一致**（设备更换或地址变化会静默污染标签）；
3. 至少 10 类设备在各选定日有足量窗口；
4. 通用 Ethernet 特征能否从 **pcap** 稳定提取；
5. 一个最小 RF LORO 任务是否可运行且无明显标签错误。

**未通过 → 立即换次选数据集，或把 RQ5 缩为仅 CPD 存在性检验。** 不得为保留模型调参而删除外部验证。

### 16.4 通过后的扩展与两个预注册检验

扩展为"连续 k 天训练、未来一天测试"，`k ∈ {1,2,3}`，控制在 100 个任务量级；类别不均衡复用 `robust_iot_research.py` 的 `sample_balanced`；入选门槛（窗口数下限）写入正文。

公开数据集**只承担两个检验**：

1. **机制存在性**：OOD `CPD_y` 是否显著高于 IID；高 CPD 划分下 Stacking gain 是否转负；
2. **方法可迁移性**：在自采数据上确定的方法是否无需重新设计即可工作（报 selection regret）。

```
检验 1 通过 → 保持机制论文 framing，公开数据集进正文（一图一表）
检验 1 不通过 → 降格为单测试床案例研究 + 方法；结果进 Discussion 作为边界条件
检验 2 通过 → 作为方法迁移性证据进正文
检验 2 不通过 → 进附录，正文限定方法适用范围为"同部署内标定"
```

**不做**：跨数据集完整基线对比、公开数据集上的深度模型搜索、特征工程调优。

**特征不必与自采数据对齐。** 802.11 专属特征（`subtype_*_ratio` / `retry_ratio` / `rssi_*` / `bssid_known` / `unique_sa/da`）在 Ethernet 抓包上不存在，只用约 60 维通用特征（`len_*` / `interarrival_*` / `burst_*` / `subwin_*` / `up/down_*`）。若 CPD 在不同特征、不同链路层、18 个类别上依然出现，则排除"CPD 是那 94 个 802.11 特征的产物"这一质疑。

## 17. Go / No-Go Criteria

### 17.1 G1 — 路线 A（`UDS` 驱动的风险选择器），2026-09-14

候选动作固定为 `RF / Stacking / soft voting`。嵌套 LOEO：内层学阈值或轻量选择器，外层只评估一次。

```
selection regret = F1(该任务事后最优候选) − F1(选择器所选候选)
```

**五项全部满足才通过**：

1. 外层平均 regret ≤ 0.01；
2. 每个环境结果完整报告，且**最差环境 regret ≤ 0.03**；
3. 相比"永远 RF"和"永远 Stacking"，平均 regret 均有改善；
4. **至少在一个外层环境正确选择非 RF**，排除"永远选 RF"的退化解；
5. `UDS` 计算不读取目标标签，**代码审计可证明无泄漏**。

**任一项失败 → 不再把路线 A 当主方法**，保留为负结果或附录，转路线 B。不得调整指标或阈值来掩盖失败。

### 17.2 G1 slip 规则

若 P0/P1/P2（见第 22 节）在 2026-09-07 未交付，G1 顺延至 **2026-09-18**；超过该日仍未具备评估条件，**默认转路线 B**。设此规则的目的是避免对未建成的方法做误杀式判定。

### 17.3 路线 B（预先定义，不等失败后临时设计）

**环境稳健的加权聚合**（单一支线，不同时开特征选择与 group-DRO）：

- 在源环境 OOF 上估计每个基模型的跨环境性能下界与错误相关性；
- 权重由源环境内层验证确定，加入向均匀权重收缩的正则项；
- 与等权 soft voting、最佳单模型、原始 Stacking 比较；
- 不使用目标标签，不把普通加权平均包装成过强的新算法。

**通过线**：平均 Macro-F1 ≥ `RF Macro-F1 − 0.005`；最差环境 F1 高于原始 Stacking；在多数外层环境取得正增益。

稳定性特征选择**只作可选消融**，不得成为第二套主方法。
