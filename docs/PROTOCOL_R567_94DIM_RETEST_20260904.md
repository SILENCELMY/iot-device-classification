## 1. 为什么这个实验现在是必须的

流程终点 ④ 的贡献 **97% 来自坐标 1**（`③−① = +0.2295`，④ 再加 +0.0060），而坐标 1
**只删了 `rssi` 一族（8 列）**。也就是说整篇论文的效应量挂在一个动作上。

而 `docs/RSSI特征分析.md` 记录：25 维时代（25→20，只删 5 列 `rssi`，源 = 联合 R2+R3+R4）
该动作在**泛化 regime 上有害**：

```
联合内部        0.9025 → 0.8358    −0.0667
位置泛化 →R5    0.6745 → 0.6531    −0.0214
抖动泛化 →R6+R7 0.7550 → 0.7310    −0.0240
```

而已冻结的 `TWO-CHANNEL-SELF` 的 9 个任务、以及消融/桥接的 11 个任务，**都不含 R5、也不含
R6+R7**（只有 3 single_round + 3 timeblock + 2 joint + 3 loro）。该反向形态在 94 维下**从未重测**。

**外部验证这条路不能替代它。** 2026-09-04 已核实：UNSW 与 CIC IoT 2022 **都是网关/交换机侧
有线抓包**（CIC 为双网卡 Windows 主机 + Wireshark/dumpcap 按 MAC 过滤，非 802.11 monitor
模式；其 idle/active 仅覆盖 40 台 IP 可达设备，Zigbee/Z-Wave 因不过 IP 网关而缺失），
故两者**都不含射频层特征**（`rssi_*` / `subtype_*` / 帧类型比例）。

> **该外部事实的出处（须随主张一并引用）**：CIC IoT Dataset 2022 官方说明
> <https://www.unb.ca/cic/datasets/iotdataset-2022.html>；以及外部验证研究
> Kostas et al., *Externally validating the IoTDevID device identification methodology
> using the CIC IoT 2022 Dataset*, arXiv:2307.08679 <https://arxiv.org/abs/2307.08679>
> （该文记录 idle/active 实际可用设备为 40 台、且仅含 LAN/WiFi 设备）。
> **本项目使用 CIC 数据的许可条件是在论文中引用其论文**（2026-09-04 用户确认许可已获得），
> 该引用义务与此处的事实引用是同一条，必须落到正文参考文献。
> 抓包位置的核实由联网检索完成（**在本机执行，未在服务器上联网、未使用任何代理**）。

因此：

- 外部数据集**无法承载 `rssi` 这一族**，坐标 1 的干预效力**在结构上无法外部复现**；
- 能外部检验的是坐标 2（元层，`m_src` 只用源域 OOF，与射频层无关）与机制的存在性；
- `MAINLINE_20260903.md` §10「没有公开 802.11 数据集只挡住**发现**的复现、挡不住**流程**的
  复现」这句话因此**同时适用于 CIC**，而非仅 UNSW。

**结论：本实验是唯一能测「坐标 1 的动作在别的漂移种类上是什么符号」的实验。** 不做，则
论文对该动作的适用范围只能凭 25 维时代的三个数字声明。

## 2. 任务与配置（运行前定死）

源域**固定为 R2+R3+R4**（`|S|=3`，与 25 维时代口径一致）。缓存已含 R2–R7
（逐轮次窗口数 R2 1816 / R3 1837 / R4 1853 / R5 1816 / R6 1988 / R7 1993），**不需重抽特征**。

| 单元 | 类型 | 目标 | 作用 |
|---|---|---|---|
| `pos_R5` | 位置变更 | R5 | **主判据单元** |
| `jit_R6` | 操作抖动 | R6 | **主判据单元** |
| `jit_R7` | 操作抖动 | R7 | **主判据单元** |
| `jit_R6_R7` | 操作抖动 | R6+R7（双目标轮次） | **主判据单元**，与 25 维时代同口径 |
| `loro_*`（3 个） | 纯跨轮次同位置 | R4 / R3 / R2（`\|S\|=2`） | 正向项，供 §5 的 `w` 权衡重算 |
| `joint_tb` | 同环境天花板 | H 内联合时间块 | 天花板代价参照 |

**配置只有两个**：

| 配置 | 列数 | 含义 |
|---|---:|---|
| `full94` | 94 | 起点 |
| `drop_rssi` | 86 | **流程实际执行的那一个动作**（`derive_families` 导出的 `rssi` 族 8 列） |

`strict59_ra`（删 35 列 + 方向修复）**不进本协议**：其列清单属 `independent/` 独立线产物，
跨线引用需另立协议；且本协议要测的是流程**实际做过**的那一个动作，不是网格里的另一个配置。

模型 = `rf` / `xgboost` / `lightgbm` / `stacking`（四个全跑，`stacking` 用于并报
`gap_vs_best_base`，即坐标 2 的信息）。种子 **42–46 五个**，报均值与样本标准差
（§14 多种子纪律；25 维时代的三个数字为单次，本协议不与其比较显著性，只比较符号）。

## 3. 主判据（运行前定死，门槛不因结果调整）

观测量 = 四个主判据单元上 `Δ best_base = best_base(drop_rssi) − best_base(full94)`，
`best_base` = 逐单元取三个非 stacking 模型 macro-F1 的最大值，再按种子取均值。

| 分支 | 条件 | 处置 |
|---|---|---|
| `HARMFUL_IN_GENERALIZATION_REGIMES` | 四个单元 `Δ < 0` | 25 维结论在 94 维复现 → **层一主张必须限定为「跨轮次同位置」**，`w` 权衡按 §5 用 94 维数字重算并进正文 |
| `BENEFICIAL_EVERYWHERE` | 四个单元 `Δ > 0` | 25 维反向证据不在 94 维复现 → 限定可放宽，但**必须如实报出与 25 维不一致**并给出解释尝试，不得只写有利的一侧 |
| `REGIME_DEPENDENT` | 混合符号 | 逐单元如实报，限定按**逐单元符号**写，不取平均掩盖 |

**任何分支都不改动 `TWO-CHANNEL-SELF` 判定**——那 9 个任务全在 `{R2,R3,R4}` 内，本协议不触碰它们。

## 4. 并报（无论方向，不得省略）

- 逐单元、逐配置、逐模型、逐种子 macro-F1（均值 ± 样本标准差）；
- `gap_vs_best_base` 在两个配置下的变化（坐标 2 视角：删列是否也改变元层损伤）；
- `joint_tb` 的天花板代价 `Δ`（删列在同环境上的代价）；
- 逐类 F1，特别是 `Socket`（历史上 96/110 条 F1=1.000，免疫性是否在 R5/R6/R7 上保持）；
- 与 25 维时代三个数字（−0.0667 / −0.0214 / −0.0240）的**符号**对照表。

## 5. `w` 权衡的 94 维重算（并报，不设门槛）

25 维时代给出：设纯跨轮次同位置占部署期比例 `w`，
`w × 0.0943 + (1−w) × (−0.0227) > 0 → w > 0.194`。
本协议用自己的数字重算：正向项 = `loro_*` 三单元 `Δ best_base` 均值；
负向项 = 四个主判据单元 `Δ best_base` 均值。**两项都用本协议实测值，不与 25 维混用。**
若负向项为正，则该权衡不存在，如实记 `NO_TRADEOFF`。
