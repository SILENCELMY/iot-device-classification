# 协议：UNSW Belkin 对的表示容量诊断（UNSW-BELKIN-CAPACITY）

**日期**：2026-09-04（运行前冻结）
**上游**：`docs/PROTOCOL_UNSW_META_MISMATCH_20260902.md`（簇定义来源）、
`results/unsw_meta_mismatch_20260902/cluster_definition.json`、`docs/MAINLINE_20260903.md` §3 模式一、§5
**性质**：诊断性测量。**不检验两通道流程、不产生任何流程判定、不删任何族、不改任何已有判定。**

---

## 1. 要回答的问题

`UNSW-META-MISMATCH` 落分支 C，事后解读把原因定位到一件**未测**的事：
UNSW 的困难簇（`BelkinWemoMotion` ↔ `BelkinWemoSwitch`，τ=0.1 下全数据集唯一一条边，
`f_ab`=0.361 / `f_ba`=0.446）**在域内就处于随机线附近**——
`src_oof_H_rf` 0.4585 / 0.5556 / 0.5167、`target_H_rf` 0.4750–0.5600、
逐类域内 F1 0.5250–0.5930（三天），而二类随机为 0.50。

对照：自采困难簇**即使删掉 `rssi`（59 列）域内仍有 0.73–0.88**
（`g0_environment_grid_strict59_ra_r5`，rf、同轮次时间块、R2–R5 的 Light_T1/Light_XM/Sensor）。

**故本协议要分开两种可能，而现有产物分不开**：

```
(A) 信息在这 61 列里，0.53 是多类干扰造成的     → 建模问题
(B) 信息不在这 61 列里                          → 表示容量问题（模式一饱和）
```

**为什么值得做**：①它是「抬天花板」这条线唯一无漂移污染的试验台
（Belkin 对域内域外都是 0.5，`regime_shift` 仅 0.0417–0.1015），自采上可分性与漂移纠缠；
②若落 (B)，`MAINLINE` §5 那条事后解读（「模式一饱和」）从推测变为测量；
③它是 §3 三种失效模式中**模式一**唯一的外部数据点。

## 2. 明确非目的

不删族、不做配置比较、不搬两通道流程、不评估任何流程判据、不改 `UNSW-META-MISMATCH` 的分支 C 判定。
**本协议不涉及 61 列之外的任何特征**；若落分支 (B)，回 pcap 找新特征须**另立协议**
（其设计依赖本协议的逐列结果，现在无法预注册）。

## 3. 数据与切分

- 特征缓存：`results/unsw_features_full/features_day_YY-MM-DD.csv`（20 天，61 特征 + 8 元数据），
  **复用不重抽**。
- **只用 H = 前 14 天**（按文件名日期升序），与 `docs/PROTOCOL_TWO_CHANNEL_UNSW_20260903.md`
  的切分点逐字一致；**后 6 天（T）本协议内不被读取**，实现以路径白名单硬性拦截、违反即中止。
  理由：T 是留出池，只读一次，不因诊断性测量烧掉。
- 门槛与平衡口径逐字对齐 `UNSW-IID-REF`：每设备每天 ≥100 窗；`sample_balanced(max_rows=20000)`。
- 域内划分：设备内按 `(window_start_epoch, window_id)` 升序前 70% 训练 / 后 30% 测试（**时间块，非随机**）。

## 4. 三个单元

| 单元 | 类对 | 特征集 | 数据 | 角色 |
|---|---|---|---|---|
| **A** | `BelkinWemoMotion` vs `BelkinWemoSwitch` | UNSW 61 | H 的 14 天，逐日域内 | **主判据** |
| **B** | `Dropcam` vs `SamsungSmartCam` | UNSW 61 | 同上 | **有效性正控** |
| **C** | `Light_T1` vs `Light_XM` | 自采 `full94` | R2/R3/R4 同轮次时间块 | 参照，**只报不设门槛** |

单元 B 的作用：证明测量本身没坏。两台不同厂商摄像头域内多类 F1 已知 0.9271–0.9997，
二类应更高；**若 B < 0.90 则判 `INVALID_RUN_STOP`，不写任何结论**——
否则单元 A 的低分无法与实现缺陷区分。

单元 C 的作用：把「自采困难簇域内可分」从多类口径换成与 A 同形的二类口径，使对照同量纲。
**不设门槛**，因跨线（自采 vs UNSW）特征集不同、样本量不同，只作定性参照。

模型：`rf` / `xgboost` / `lightgbm` 三个基模型（**不含 stacking**——容量问题与元层无关）。
种子 **42–46**，报均值与样本标准差。

## 5. 主判据（运行前定死，门槛不因结果调整）

主量 = **单元 A 的二类 macro-F1**，逐日逐种子逐模型算出后，先按种子取均值、
再按天取均值、最后**取三个模型的最大值**（与 `best_base` 口径同构）。

| 条件 | 状态码 | 含义与处置 |
|---|---|---|
| `>= 0.80` | `SEPARABLE_IN_BINARY` | 信息**在**这 61 列里 → 落 (A) 建模问题；`MAINLINE` §5「模式一饱和」那句**必须撤回并改写**，多类 0.53 归因于多类干扰 |
| `0.60 =< F1 < 0.80` | `PARTIALLY_SEPARABLE` | 部分信息在 → 两种成因都有，逐列结果决定后续 |
| `< 0.60` | `NOT_SEPARABLE_IN_61` | 信息**不在**这 61 列里 → 落 (B)，「模式一饱和」由推测升为测量；回 pcap 另立协议有据 |

**门槛依据（选定于任何本协议数字之前）**：
- **0.60**：二类随机为 0.50，而 Belkin 对现有多类逐类 F1 为 0.5250–0.5930；
  取 0.60 即「显著高于随机、且高于现有多类值的上端」。
- **0.80**：与 `docs/PROTOCOL_CIC_RANGE_ANCHOR_20260904.md` §「可分性与漂移的归因分离」
  所用的 `同日 IID F1 >= 0.80` 门槛**同一个数**，跨协议口径一致，不另设。

## 6. 并报（无论方向，不得省略）

1. **逐列单变量 AUC**：61 列各自作为分数对单元 A 打分（H 内逐日算、按天取均值），
   报 **max**、top-10 清单、以及按 UNSW 7 族（`derive_families` 机械导出：
   `len`14 `interarrival`12 `subwin`9 `burst`7 `up`7 `down`6 `singletons`6）聚合的族内 max。
   **只报不设门槛**——单列 AUC 的先验门槛无法诚实论证。
   **读法（运行前写定）**：若 `max 单列 AUC < 0.60` 而单元 A 的 F1 `>= 0.80`，
   则信息是**多变量**的（任何单列都不够）；若两者都低，则信息**不存在于这 61 列**。
2. 单元 A/B/C 的逐日、逐模型、逐种子 macro-F1 与逐类 F1、混淆矩阵。
3. 单元 A 的**跨天**对照（H 内逐配对，同口径）：用于确认 Belkin 对是可分性问题而非漂移问题
   —— 预期跨天与域内接近（现有证据 `regime_shift` 0.0417–0.1015）。**只报不设门槛。**
4. H 内 14 天逐日两设备的窗口数；被 ≥100 窗门槛剔除的天（若有）。
5. 单元 A 与 C 的 F1 差值，**明写这是跨数据集比较、不构成受控对比**。

## 7. 六道硬门（任一失败即停，不写结论）

2. **`window_start_epoch` 不在特征中**，逐项核对并落盘（UNSW 已记录的坑：
   含它与 `day` 共线 → 同日虚高、跨天崩坏）；8 个元数据列一律不入特征。
3. **单元 B 有效性正控** `>= 0.90`，否则 `INVALID_RUN_STOP`。
4. 特征缓存复用不重抽，`features_day_*.csv` 的 md5 先于任何模型数字落盘。

   线程三变量 `OMP_NUM_THREADS=MKL_NUM_THREADS=OPENBLAS_NUM_THREADS=1` 且 `n_jobs=1`；
   **双跑之间不得提交任何 commit**（`HISTINT-OBJ-SIGNAL` 已记该教训：`git_head` 会使 provenance 不一致）。
6. 解释器 `~/anaconda3/envs/iotcls/bin/python`，**全程禁网、禁代理、不安装依赖**。

## 9. 预估成本

单元 A/B 各 14 天 × 3 模型 × 5 种子 = 210 次二类拟合（每次约 2 万行 × 61 列）；
单元 C 3 轮次 × 3 模型 × 5 种子 = 45 次。逐列 AUC 为 61 × 14 次单变量排序，可忽略。
按 `UNSW-IID-REF` 实测（13 类、1.7 万行、1.2 s/次）折算二类更快，
预计 **< 15 min/单跑、< 30 min/双跑**。
