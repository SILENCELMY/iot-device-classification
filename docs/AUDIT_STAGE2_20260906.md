## 1 ✅ 多对施加时区重叠，后写覆盖先写

```python
pred = o1.copy()
for (i,j) in cfgs:                     # dict 顺序
    pred[sel] = ...                    # 后写覆盖先写，无冲突消解
    acc_o = (pred[sel]==yo[sel]).mean()   # 在【累积后】的 pred 上量
```
先施加那一对报的数，是在它被后一对覆盖**之前**量的 ⇒ 逐对数字依赖 dict 顺序，
且不一定等于最终 `pred`。

**实测（`audit_overlap.py`，CIC 已烧天）**：过闸三对压在
`{GlobeLamp, GosundPlug, GosundSocket}` 三个类上——
```
GosundPlug|GosundSocket ∩ GlobeLamp|GosundSocket   交集 3031/3037 = 99.8%
GosundPlug|GosundSocket ∩ GlobeLamp|GosundPlug     交集 2794/2804 = 99.6%
GlobeLamp|GosundSocket  ∩ GlobeLamp|GosundPlug     交集 0（互斥）
被写 ≥2 次的窗 5825（占被覆盖窗 19078 的 30.5%）
6 种施加顺序：端到端 min 0.8816 / max 0.8826，极差 0.0009
对照：第二段增益区间 [+0.0029, +0.0038]
```
**极差 = 增益的 27%。** 不到"同量级"，但不可忽略：论文里不能出现
"四分之一的增益取决于 dict 遍历顺序"。

**修法**：(a) 施加顺序**按区大小从大到小**——确定、可复现，且语义合理
（小区是模型更笃定的判决区，应覆盖大区）；(b) 逐对记账在**全部写完后的最终 `pred`** 上统一重算。

**影响范围**：UNSW C3 确证只过闸 1 对，**不受影响**；**CIC 那条 +0.003 需用修后代码重算**。

## 7 ⏳ 第二段的输出没享受第一段的因果平滑（本次审计最重要的一处）

```python
pbase = 平滑后的基模型概率，限制到 {i,j} 归一     ← 已平滑
q     = 专用二分类器的【逐窗原始】概率           ← 未平滑
mix   = 0.5*pbase + 0.5*q
```

**实测（`blend_smooth.py`，已烧天，探索性不进主线）**：
```
区上           w      16-09-30  16-10-11  16-10-12
A 专用原始    0.50    0.5781    0.6844    0.6812
              1.00    0.6029    0.6188    0.6275   ← 施加天低于在位者
B 同口径平滑  0.50    0.7036    0.7578    0.7712
              1.00    0.7835    0.7804    0.7876   ← 三天全是峰值
在位者                0.5097    0.6294    0.6322

端到端第二段增益  A@0.5  +0.0137  +0.0107  +0.0096   ← C3 确证用的形态
                  B@1.0  +0.0511  +0.0286  +0.0298   ← 施加天上约三倍
```

**结论**：方法有两段，但第一段只作用在基模型上，**没作用到第二段的输出上**。
融合（w<1）之所以有效，是掺进平滑过的基模型概率**顺带降噪**——一个粗糙的替代品。
补上同口径平滑后 `w=1.0` 最好，**`w` 这个参数消失**。

**⚠ 这推翻了同日早些时候的机制解释**（"硬替换扔掉基模型信息、两边错不重叠"）。
教训：**一个解释能预测数据，不代表它是对的机制——尤其当更简单的替代解释没被检验时。**

**处置**：C3 确证仍然有效（测的就是代码做的事，协议 §4 未规定专用侧平滑），
`+0.0080` 是真的；但改进形态**只在已烧天上量过，无确证地位**，且 UNSW 保留集已用掉。
待定：用 CIC 做改进形态的预登记确证（CIC 未被用作确证集，且是身份型，可检验另一种难度类型）。

## 8 ✅ RF 双重加权，与 lr 口径不一致

```python
MK("rf") → RandomForestClassifier(..., class_weight="balanced")   # 第一次
fit_w()  → m.fit(X, y, sample_weight=compute_sample_weight(...))  # 第二次
```
sklearn 中两者**相乘** ⇒ RF 少数类权重被**平方**；`MK("lr")` 未设 `class_weight`，只加权一次。
**⇒ 配置搜索里"选 rf 还是 lr"不是同一条件下的比较。**

**修法**：RF 去掉 `class_weight`，两个模型都只在 `fit_w` 里加权一次。
**基模型（RF300）只有 `class_weight`、不传 `sample_weight`，本来就是单次加权，不受影响。**

## 9 ✅ 加权拟合失败静默退回

`except Exception: m.fit(X,y)` 吞掉一切异常并退回**不加权**模型，无任何提示。
84 个候选里若有几个悄悄退化，看不出来。**修法**：打印一次警告（按模型名去重，不刷屏）。

## 3+4 ⏳ 选择用的量 ≠ 判定用的量（两者是同一件事的两面）

```python
if loc[2]-inc > best[3]-best[4]: best=(rn, ...)   # 按【区上准确率增幅】选
```
- **按"率"不按"量"**：三个区大小差近 2 倍（Belkin：R2 5321 / R3∩R1 6054 / R3 9763），
  小区上的高增幅改对的绝对窗数可能更少。
- **选择量 ≠ 判定量**：闸门按区上准确率选，论文按 macro-F1 判。
  **今天实测过一次分岔**：区上 −0.0237 而 macro +0.0024
  （机制：macro-F1 逐类平均，判决推向弱召回类会抬它的 F1；区上准确率类盲）。
  这次 C3 确证没被咬到（区上 +0.0417、macro +0.0080 同向），但**错位是结构性的**。

**修法**：直接按**选参天的端到端 macro-F1** 选候选——那就是被判定的量，
且天然处理区大小问题。成本可忽略（84×8=672 次 `f1_score`，47k 行，几秒）。

## 5 ⏳ 84 候选取单天最大值，选择偏差与 MARGIN 同量级

每对搜 14 掩码 × 2 模型 × 3 区 = **84 个候选**，取单个选参天上的最大值，
只有 `MARGIN=0.02` 把关。区 n≈5000–10000 时准确率标准误约 0.005，
**84 个取最大，上偏 0.01–0.015 属正常，与 MARGIN 同量级。**

**已有证据**：选中的配置 选参天 +0.0684 → 保留集 +0.0417，**缩水 40%**。
方向对（故确证通过），但缩水幅度正是选择偏差的典型形状。

**修法（不需要新数据）**：选参天按时间劈两半——前半选配置，
后半要求它**仍然**打赢在位者 + MARGIN，两关都过才放行。
区劈半后仍有 2500–5000 窗，够用。

## 6 ⏳ 困难对取选参天错误量前 8（魔数）

`hard = err.most_common(8)`，8 是拍的。且在目标天成问题、选参天不成问题的对，
**永远进不了闸门视野**。

**修法**：改由**账本**产生候选对——账本已逐对算了错误占比与对内准确率，
让它判定为"未解"的对进入闸门视野。有原则、自适应数据集，
且把方法的**仪器**（账本）与**干预**（闸门）接起来。

**底层限制改不掉**：只能在源域导出、目标域无标签。**写进论文局限。**

## 审计本身的方法学收获

十处里，**四处（1/7/8/9）是"实现没做到方法声称的事"**，
三处（3+4/5/6）是"方法定义本身需要改进"，三处是局限。

**四处真缺陷有共同形状：某个操作只施加在了一半的对象上。**
```
1  记账施加在子集、动作施加在超集
7  平滑施加在基模型、没施加在专用模型
8  加权施加了两次（RF）、一次（lr）
9  加权在失败时施加了零次，且无声
```
⇒ **写这类代码时的检查项：每个操作，问一遍"它作用在哪些对象上？有没有漏掉对称的另一半？"**
