**两半都属于本方法**——平滑是「位移下复杂度不买账」这一主张在时间轴上的推论，
与 always-RF 同源，不是外部基线；且闸门的定义里就含平滑（「相对已平滑的在位者有增益才动手」），
没有平滑当在位者就退回 v2 的 +0.0243，两者在设计上不可分。

**但仍必须拆开报，因为两半的代价不同**：平滑不要标签、不要 inner 环境、不要逐类对机制，
任何人立刻能用；定点修要 ≥2 个有标签环境 + 逐类对搜 (模型, 时长) + 闸门。
读者要据此决定「只做便宜那半够不够」，合成一个数字他判断不了。

## 两层，各治一种失效模式

- `smooth_control.py` —— 全局同流因果时间平滑（基模型多分类概率在同一流连续 k 窗上平均，
  k 在 inner 上选）。治**方差**。零拟合参数、零容量。
- `cfg_v3.py` —— 逐类对 (模型, 时长) 配置，**只在 inner 上打得赢已平滑的在位者 + margin 0.01
  时才覆盖**。治**偏差**。

**闸门是关键**：`cfg_joint.py`（绝对闸门 AUC≥0.95）在 44/45 对上动手，UNSW 只得 +0.0243，
因为在 8 个容易类上每次都赔一点；改成相对在位者后只动 1–2 对，变 +0.0723（2.5×）。

逐类 F1（UNSW seed42）显示两者互斥：

```
                  base     平滑k3   平滑k10   v2全覆盖
BelkinWemoSwitch  0.4678   0.5285   0.3189   0.8936
BelkinWemoMotion  0.6343   0.7421   0.7090   0.8751
其余 8 类          —        0.94–1.00        全部低于平滑
```

平滑在最难的类上不但没用，k=10 时反而压到 0.3189（低于不平滑）——
**平滑降方差、固化偏差**：基模型系统性判反的对，平均越多越确定地错。

## 关键诊断

- **`pair_auc` 用 LR、部署用树**，逐类对 AUC 差 0.15–0.86 且方向相反
  （GlobeLamp LR 0.9997 / xgb 0.1431；Netatmo LR 0.4194 / RF 0.9934；Belkin LR 0.6917 / RF 0.5389）。
  机制：树的分裂点钉在源域取值上，目标域落到区间外被路由到错误叶子。
  **此前所有基于 `pair_auc` 的分型结论需按此重算。** → `hard_pair_rescue.py`
- **观测时长**：Belkin 0.6917 @k=1 → 1.0000 @k=10，三个迁移任务一致。→ `hard_pair_rescue.py`
- **top-2 覆盖天花板**：UNSW +7.38 / +9.98 / +11.63 点，CIC +11.29 点。→ `top2_ceiling.py`
- **CIC 机制开火但不兑现**：L1 3/7 正值族（UNSW 0/7），过下限的 26 对 100% 含 AMCREST，
  但 Δmacro ≈ 0——开火的全是本来就判对的。→ `cic_probe_gate.py`
- **捕获内时间留出不足以证明设备身份**：同域时间块 AUC 1.0000，换一次抓包跨域 0.15 → 0.92。
  对自采所有 in-domain 参考值同样适用。→ `cic_invert.py`

## 与项目主张的关系

「环境位移下复杂度不买账」的第四、第五次验证：
④ 零参数的平滑打赢了我们建过的全部复杂机制（stacking / 元模型 / 特征掩码 / 容量搜索）；
⑤ 逐类对选模型时程序几乎从不选最高容量的——v2 的 44 对里 xgboost 只中 1 次，v3 的 3 对里 0 次。
修复动作是**退到更简单的模型**（LR），不是更复杂的。

## 为什么闸门要改两次

**v3/v4 的判据测错了总体。** 同一个类对，在「两类的全部窗口」上逐类对 AUC = 1.0000，
在「这两类争 top-2 的窗口」上是 0.03——全体上的高分被大量轻松判对的窗口撑着，
恰好把决策真正发生的那一小块掩盖掉。而且 AUC 对切点免疫，两个毛病叠在一起。
v5 改成**可判决区上的准确率**，一次解决两个：换对了总体，且准确率按实际判决规则算。

诊断能力的提升是实的：CIC 过闸从 12/350 变成 7/74，且每一对的病看得清清楚楚
（在位者准确率 0.0000 这种，在 AUC 口径下完全看不见）。

## CIC 的最终归因：五个假设，四个证伪

| # | 假设 | 结果 |
|---|---|---|
| ① | inner 与 outer 位移不同型 | **证伪**：同型化 −0.0045 → −0.0048 |
| ② | top-2 覆盖够不着 | **证伪**：可及率 +25 点（42.0%→66.9%），收益 +0.0026 |
| ③ | 切点 | 测试被子集类别不平衡混杂，不可读；被 v5 的准确率判据绕过 |
| ④ | 闸门测错总体 | **一半成立**：诊断大幅改善，但端到端仍 +0.0017 |
| ⑤ | **逐类对修复在 CIC 上不跨日迁移** | **剩下的解释**，证据最强 |

⑤ 的证据：v5 在 inner 上把 `GlobeLamp|Gosund039AAF` 从 0.0000 修到 0.8909、
`GlobeLamp|Gosund032979` 从 0.1098 修到 0.9294，**六对合计可判决区约 1000 窗**，
到 outer（1108Active）只兑现 +0.0019。**修得出来、迁不过去。**

**故适用条件应写成：逐类对关系需跨环境稳定——而这可用两个 inner 环境对交叉检验，
不稳就不动手。** UNSW 满足，CIC 不满足。

# 更正：上一节「CIC 上不存在方法可作用的空间」是错的

上一节据 `(25 × 0.8130 + 11 × 0.1403) / 36 = 0.6074` 断言 CIC 没有可回收的量。
**该结论已被推翻**：那 11 台 ESP 插座同芯片同固件，把它们算成 11 个类，
相当于同一款设备测了 11 次。现实用途（分段 / 策略 / 清点 / 异常基线）全是**型号级**；
实例级身份需时钟偏斜这类物理层指纹，流量统计原理上做不到。
**实例级标签是数据集产物，不是任务定义。**

## 实测（同一批数据、同一模型，只改标签空间）

```
                     跨日 1102Idle → 1108Active
实例级   36 类        0.6074  → 平滑 0.6861
型号级细 29 类        0.7584  → 平滑 0.8705    （Gosund Plug / Socket 分开）
型号级粗 28 类        0.7980  → 平滑 0.9181    （Gosund 全系合一）

合并表（细）：AmazonAlexaEchoDot ×2、GosundPlug ×4、GosundSocket ×2、TeckinPlug ×2、YutronPlug ×2
合并表（粗）：AmazonAlexaEchoDot ×2、GosundPlugSocket ×6、TeckinPlug ×2、YutronPlug ×2
```

`GosundPlugSocket`（6 台合一）跨日 **0.905**；合并前那 6 台各自 0.00–0.18。
**它们分不开的只是彼此，型号本身一直可识别。**

## 型号级之后剩下的困难簇是真的，而且形状正好

```
GlobeLampESPB1680C  0.000     TeckinPlug 0.464     YutronPlug 0.575
GosundPlugSocket    0.905     其余 24 类 0.94–1.00

可回收量 (1−0.000 + 1−0.464 + 1−0.575 + 1−0.905) / 28 = 0.073
```

四个 ESP 系型号互混（Gosund / Teckin / Yutron 插座 + GlobeLamp 灯）——**是有意义的任务**，
且与 UNSW 上「10 类里 2 类扛 0.075」同量级、同形状（少数类、错误集中、彼此是不同设备）。

**方法在 CIC 上测不出效果，不是池子空，是评估口径把可作用的结构碾成了 11 个随机类。**

## 操作要求

- CIC 一律用**型号级**评估，报告里明写理由与合并表；数字不可直接与按实例级报结果的文献比。
- 合并只适用于「同型号多实例」。**自采的困难簇不可合并**——`Light_T1`/`Light_XM`/`Sensor`
  是三种功能不同的设备共用一个小米网关，合并等于放弃任务。
- 时间平滑的分组仍按**物理流（MAC）**，不按合并后的标签。
- 合并后型号类的训练窗口成倍增加（GosundPlug 4×），对它有利且合理，须在报告里记明。
- **评估任何新池子，第一步先测同域 macro、逐类分布，并检查标签空间是否是任务定义而非数据集产物。**

# 型号级重跑 v5：缺口是真的，但属于表征层

```

困难类逐位不动：GlobeLamp 0.000→0.000、TeckinPlug 0.464/0.633、YutronPlug 0.575/0.752
```

闸门审计给出原因：

```

```

**候选 (模型, 时长) 里不存在能分开 ESP 灯和 ESP 插座的东西。** 闸门只放行 2 对、增益微小，
**是正确行为，不是失灵**。

## 方法有没有用的判别式（可在 inner 上预检，不需要 outer 标签）

```
UNSW  Belkin      在位者 0.5489 → 配置 0.9978    存在能修的配置  → 方法 +0.075
CIC   GlobeLamp   在位者 0.6607 → 配置 0.7091    不存在          → 方法 −0.0003
```

## CIC 的账分三层，性质各不相同

1. **实例级 0.6074** —— 标签空间错误（11 台同款插座算成 11 类），不是任何真实问题
2. **型号级 0.9253** —— 修正标签后的真实水平
3. **剩余 0.073 缺口** —— **表征极限**：这 61 个统计特征里不存在能跨捕获分开 ESP 系型号的量。
   **要动它得加特征，不是换配置。** 方法在这一层正确地报告「我做不了」。

另记：合并后 `GosundPlugSocket` 有 6 倍窗口，6:1 不平衡下少数类几乎判不出来；
但 `GlobeLamp` 在实例级时也是 0.000，不是合并造成的。


**真信号足够强时，更大的空间能找到更好的解；真信号弱时，更大的空间只是把
144 选 1 的噪声最大值抬高。** 这解释了为什么 v6 的 inner 增益比 v5 大 3.5 倍
（GlobeLamp 那一对 +0.038 → +0.132）而 outer 纹丝不动 —— 多出来的是选择偏差，
不迁移（winner's curse）。

# 自采数据（P0-1）：两段式 —— 平滑只在它合法的那一层做

**设计依据（用户提出）**：平滑的分组依据是"同一个可观测流"。自采恰好有三个流：
Camera 自己的发射机、小米网关（内含 `Light_T1`/`Light_XM`/`Sensor` 三台）、Socket 自己的发射机。
**平滑在发射机这一层合法**（部署时看得见 MAC）；流内部三台交织，那一层不能平滑。

```
第一段  3 类（Camera / Gateway / Socket）   平滑合法，按发射机分组   inner 上 macro = 1.0000（不平滑 0.9673）
```

## 程序独立重新推导出了项目的起点发现

五个 seed 全部选出同一对、同一配置，逐格一致：

```

  A（R2→R3）  在位者 0.0029–0.0030 → 配置 0.8947–0.9046
  B（R3→R2）  在位者 0.0158–0.0374 → 配置 0.8612–0.8637
```

**在位者准确率 0.003 —— 基模型在这个可判决区上几乎全判反。** 而"删 rssi"正是本项目
最早的那个发现（`rssi-ablation-is-the-origin`，当年是人工试出来的、结论反复摇摆）。
**程序在未被告知任何族的物理含义、也不知道 R5 是位置轮次的情况下，自己选出了它，
并且只在位置漂移的单元上兑现：**

```
pos_R5   +0.0570 / +0.0572 / +0.0592 / +0.0607 / +0.0608     位置漂移，rssi 失效
jit_R6   ≈ −0.001                                            操作抖动，rssi 未坏
jit_R7   ≈ +0.002
```

这也与老结论表面矛盾、实则一致：老结论说的是**全局删 rssi 在 R5/R6/R7 上有害**；
这里是**只在 `Light_T1|Sensor` 这一对、且只在它们争 top-2 时掩掉 rssi**。
**全局删有害、定点掩有益 —— 正是方法的核心主张，这次在项目自己的起点发现上得到验证。**

## 三条保留

1. **`flat 0.7854` 与 `flat_183 = 0.8072` 差 0.0218**，归因于"单模型 vs `best_base` 三模型"，
   **尚未实测**（`verify_flat.py` 待跑）。在此之前"可比"只是推断。
2. **5 个 seed 只反映模型初始化的随机性** —— 数据不重采样，五次看到的完全相同
   （与 `override_183` 的约定一致）。方差极小（pos_R5 上 0.0570–0.0608）是这个原因造成的。
3. **增益集中在一个单元**。准确说法是"**方法在位置漂移下有效，在操作抖动下不动**"，
   而非"方法在自采上有效"。

## 一处自我更正

曾把"双 inner 优于单 inner"解释为 winner's curse 对策（剔除了噪声配置）。
**seed45 两臂都只过 1 对，差距照旧 +0.008 vs +0.061 —— 该解释被证伪。**
真正的差别是**两个臂看到了不同的世界**：

```

双 inner（R2→R3，|S|=1）      Light_T1|Sensor 在位者 0.0029 —— 认为几乎全判反
```

而 outer 证明后者判对。但该臂同时改了两件事（inner 的 `|S|`，与第二环境验证），
**功劳归属未定**，需消融（`cfg_ablation.py`）。
另注：这与 `rssi-ablation-is-the-origin` 记录的"`|S|=1` 有误导性、`|S|≥2` 是硬要求"
方向相反 —— 两者测的量不同（那次是 `d_auc`，这次是可判决区准确率 + 端到端 macro），
**不算直接矛盾，但必须调和后才能把任何一条当规则。**
