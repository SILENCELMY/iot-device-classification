## 1. 要回答的两个问题

### 1.1 背景（今日实测，非本协议产出）

自采数据集在 802.11 空口上只有 **3 个发射机**，却打了 5 个标签（数据集作者已确认拓扑）：

| 标签 | 空口发射机 `wlan.ta` |
|---|---|
| `Camera` | `78:df:72:04:d6:b4` |
| `Socket` | `b8:50:d8:67:b5:d0` |
| `Light_T1` / `Light_XM` / `Sensor` | **同一个** `54:ef:44:59:eb:4c`（小米网关，三者为其后的 Zigbee/BLE 设备） |

`FILTER_EXPRESSIONS["raw_all"] = None`，故 94 列缓存**无任何 MAC 过滤**，标签仅由 pcap 文件名决定。

**该拓扑在本协议中是声明的输入（真值），不是本协议的结果。**

### 1.2 烧毁披露（必读，决定本协议的设计）

`FEATURE-EXPANSION-SELF` 的并报项里，`rssi` 的逐类对 `d_auc` 呈现如下符号模式，
**该模式是在本协议撰写之前被看到的**：同发射机的 3 个类对全为正、Camera 对网关三类的 3 个类对全为负、
含 `Socket` 的 4 个类对绝对值 < 0.001。

该观测来自 `TASKS` 的 9 个 g0 任务，其目标域**全部落在 R2/R3/R4 之内**
（`g0_R2_R3_to_R4`、`g0_R2_R4_to_R3`、`g0_R3_R4_to_R2`、`g0_R2_to_R3`、`g0_R2_to_R4`、
`g0_R3_to_R2`、`g0_R3_to_R4`、`g0_R4_to_R2`、`g0_R4_to_R3`）。

**故：目标域在 R2/R3/R4 的任务对本协议第 A 部分已烧毁，本协议不使用。
R5 / R6 / R7 从未被该诊断读取，本协议的预测在其上检验。**
用于定 τ 的量级校准取自已烧毁数据（§3.3），此点在此披露；判据本身在未读数据上执行。

### 1.3 两个共同主判据（不可相互替代）

- **A**：`rssi` 的逐类对 `d_auc` 符号，能否在**未读轮次** R5/R6/R7 上还原发射机划分？
- **B**：在 **R6（05-26，三个网关设备同日采集）** 这一日期被完全固定的单元上，
  三个网关类的逐类 F1 是多少？——判定它们的分离是**设备信号**还是**日期残留**。

**A 与 B 都必须报出，任一方向都不得省略；一方失败不得用另一方替代。**

### 1.4 为什么 R6 是决定性单元（运行前定死的理由）

各 (设备, 轮次) 会话的日期与时段（今日实测）：

| 设备 | R2 | R3 | R4 | R5 | R6 | R7 |
|---|---|---|---|---|---|---|
| `light_T1` | 05-09/10h | 05-15/10h | 05-21/16h | 05-13/09h | **05-26/17h** | 06-02/16h |
| `light_xm` | 05-09/09h | 05-12/16h | 05-15/09h | 06-05/10h | **05-26/16h** | 06-02/15h |
| `sensor` | 05-08/10h | 05-12/15h | 05-14/17h | 06-05/09h | **05-26/14h** | 06-01/09h |

每个 (设备, 轮次) 只有**一场**约 1 小时会话，故对这三个共用发射机的类，
「设备身份」与「会话身份」在数据内不可分离。两项缓解在数据中已存在：

1. **时段已平衡**：三个网关类各自恰好 **3 场上午 / 3 场下午**，故时段不构成跨轮次仍存活的逐标签关联；
2. **R6 三个网关类同日（05-26）**：日期、环境、网络状况完全固定，仅设备与小时不同。

**残余未控项（如实记）**：R6 上小时仍不同（17h / 16h / 14h）。彻底解开需会话交织式重采，本协议不做。

## 3. 第 A 部分：符号还原发射机划分

### 3.1 观测量（复用冻结实现，不重实现）

逐 (单元, 无序类对)：
`d_auc = pair_auc(full94_minus_rssi) − pair_auc(full94)`
`pair_auc` 逐字复用 `run_two_channel.py:198`（源域拟合标准化逻辑判别、目标域 AUC，
`max_iter=2000, C=1.0`，样本门槛 40/20）。

逐类对统计量：`D(pair) = Σ_{单元 ∈ {R5,R6,R7}} d_auc(pair, 单元)`（与 `d_auc_sum` 同构）。

### 3.2 预测规则（机械，运行前定死，按优先级）

对每个类对，符号判定：`+` if `D > τ`；`−` if `D < −τ`；`0` if `|D| ≤ τ`。

**预测**（优先级从上到下，第一条命中即止）：

1. 两端**共用发射机** → 预测 `+`
2. `full94` 基线 AUC（三单元均值）**≥ 0.999**（饱和，无余量） → 预测 `0`
3. 其余（不同发射机且未饱和） → 预测 `−`

规则 2 依赖运行中测得的基线 AUC，但**规则与饱和阈值 0.999 均在此定死**，
故预测是该测量的确定性函数，不含运行后的自由度。

**在"`Socket` 保持饱和"这一假设下，规则展开为如下 10 条**（一并列出以便读者对照；
若 `Socket` 在 R5/R6/R7 上未饱和，则按规则 3 改判为 `−`，此为规则的执行、不是改判据）：

| 类对 | 同发射机 | 预测 |
|---|---|---|
| `Light_T1｜Light_XM` | 是 | `+` |
| `Light_T1｜Sensor` | 是 | `+` |
| `Light_XM｜Sensor` | 是 | `+` |
| `Camera｜Light_T1` | 否 | `−` |
| `Camera｜Light_XM` | 否 | `−` |
| `Camera｜Sensor` | 否 | `−` |
| `Camera｜Socket` | 否 | `0`（饱和） |
| `Light_T1｜Socket` | 否 | `0`（饱和） |
| `Light_XM｜Socket` | 否 | `0`（饱和） |
| `Sensor｜Socket` | 否 | `0`（饱和） |

### 3.3 τ = 0.01（定于任何本协议数字之前）

校准来自已烧毁的 R2/R3/R4 观测（§1.2 已披露）：那里 9 个任务上，
含 `Socket` 的 4 个类对 `|d_auc_sum| ≤ 0.0008`，其余 6 个类对 `|d_auc_sum| ≥ 0.4247`。
折算到 3 个单元：饱和带上界 ≈ 0.0003、信息带下界 ≈ 0.1416。
**τ = 0.01 位于两者之间，距饱和带 ~33×、距信息带 ~14×**，非贴边取值。

### 3.4 主判据 A（门槛不因结果调整）

`hits` = 10 个类对中符号与预测一致的个数。

| 分支 | 条件 |
|---|---|
| `PARTITION_RECOVERED` | `hits = 10` |
| `PARTITION_PARTIAL` | `hits ∈ {8, 9}` |
| `PARTITION_NOT_RECOVERED` | `hits ≤ 7` |

**门槛依据**：三元符号判定，随机命中率 1/3，`P(hits=10 | 随机) = (1/3)^10 ≈ 1.7×10⁻⁵`；
`P(hits ≥ 8 | 随机) ≈ 3.4×10⁻³`。取 `10/10` 为完全还原、`≤7` 为否证，
中间两档记为部分还原（8/10 时随机解释已可排除，但划分未被完整还原）。

## 4. 第 B 部分：同日单元的逐类 F1

### 4.1 观测量

逐 (单元, 配置, 种子)：三个模型各训一次，取 **macro-F1 最大者**为 `best_base`
（口径与 `R567-94DIM-RETEST` 一致），报**该模型的逐类 F1**（5 类全列），再对 5 个种子取均值。

### 4.2 主判据 B（门槛不因结果调整）

主量 = **单元 `R6`、配置 `full94_minus_rssi`** 下
`{Light_T1, Light_XM, Sensor}` 三类逐类 F1 的均值，记 `F_gw`。

| 分支 | 条件 |
|---|---|
| `DEVICE_SIGNAL_SAME_DAY` | `F_gw ≥ 0.50` |
| `AMBIGUOUS` | `0.40 ≤ F_gw < 0.50` |
| `NO_DEVICE_SIGNAL` | `F_gw < 0.40` |

**门槛依据（定于任何本协议数字之前）**：若三个网关类不可区分，分类器在三者间的分配
退化为随机，逐类 F1 → **1/3**（三类窗口数近似均衡）。`0.50 = 1.5 × (1/3)`，
`0.40 = 1.2 × (1/3)`。跨池外部参照：`strict59`（无 rssi）在**不同日**的
`g0_R3_R4_to_R2` 上三类召回为 0.766 / 0.896 / 0.849（均值 0.837）——
**该参照来自不同特征集与不同单元，不构成受控对比**，只用于说明 0.50 是宽松下界。

### 4.3 为什么主判据 B 定在 `full94_minus_rssi`（运行前给出的理由）

B 问的是"日期固定时是否存在设备关联信号"。`rssi` 对这三个类对
**在物理上不可判别**（同一电台、同一位置），故其权重必为噪声拟合；
纳入它测到的是反转的严重程度，不是设备信号。
**`full94` 一并报出**（§5.3），两者之差即该噪声块的代价。
