# 项目现状说明（外部审阅用，2026-09-02）

给没有本项目历史的读者。目的是让你在读任何历史文档之前，知道**哪些结论现在还成立、哪些已被自己判否、哪些没测过**。

## 0. 一句话

研究加密 802.11 空口流量下的 IoT 设备识别，**为什么模型跨采集轮次会失效**。
昨夜（09-01→09-02）项目发生了一次结构性转变：原来的核心主张已被自己的检验解体，
取而代之的是一条四层链条，其中最强的一环从相关系数换成了逐窗口的直接测量。

## 1. 转变前后

**转变前的主线**：跨场景 → 混淆模式漂移（CPD, Confusion Pattern Drift）→ 破坏集成互补性 → Stacking 失效。
CPD 是一个混淆矩阵漂移的标量。

**这条主线的现状（全部是本项目自己的预注册检验判否的）**：

| 检验 | 结论 |
|---|---|
| E2 分层回归 | `CPD_y` 增量解释力消失：ΔR² **+0.0066**、β −0.245 [−0.757, +0.320] 跨零、留一环境 CV 变差 4.6% |
| G1 路线 A（无标签选择器） | regret **0.02469** vs always-RF **0.02025**，反而更差 |
| 路线 B（环境稳健加权） | macro-F1 **0.661379** vs RF **0.687025**，缺口 −0.0206（容差 0.005 的四倍） |
| M4（固定无标签可观测量） | 恢复 48.81%，门槛 80% |
| M5-T（加无标签时间结构） | 58.43%，`STOP_ROUTE_C` |
| M6（跨数据集设备行为） | `CROSS_DATASET_BEHAVIOR_NOT_STABLE_STOP` |
| D12 / UNSW 检验 1 | `partial_default_not_pass`（判据 1 的 bootstrap CI 跨零） |

**结论**：CPD 作为机制、预测量、部署指标一律不成立；无标签部署方法三族全否。这些判定不再重开。

**转变后的结构**（四层，注意层四是旁支不是下游）：

```
层一  表示：非不变的采集条件量在场（RSSI、802.11 subtype、retry 等 35 列）
          │
          ↓（推断，未测）
层二  簇：存在可混淆簇，且簇内在源域 OOF 上近乎不可分
          ├──────────────────────────┐
          ↓（已测 rho -0.753）        ↓（未单独检验）
层三  元层：类别定向重标注 = EC-MDM   层四  基模型混淆矩阵漂移 = CPD
```

层四之所以是旁支:E2 里的 `CPD_y` 算在 **RF 的混淆矩阵**上，而因变量是 **stacking 的 gain**。
用基模型的错法漂移去预测元层造成的损失——两个不同对象，元层的重标注根本不进入 RF 的混淆矩阵。
这给了 E2 的失败一个原理性解释，而不只是"试了没用"。

## 2. 读数字前必须知道的口径

1. **OOF 臂**：Stacking 的 OOF 折叠有三种口径。**A 臂** = 随机 K 折（历史口径，跨轮次泄漏、偏乐观）；
   **A′ 臂** = 随机但折数对齐 B；**B 臂** = 按训练轮次分组（协议要求的口径）。
   **本文所有 Stacking 数字都是 B 臂**，除非标明。同一任务两臂可以差很多：
   `loro_R2_R3_to_R4` 的 gain 在 A 臂是 −0.0028（"接近持平"），B 臂是 **−0.2236**。
   历史文档 `STACKING_COLLAPSE_ANALYSIS` 整篇是 A 臂，其顶部有口径警告。
2. **`gap_vs_best_base`** = `macro_f1(stacking) − max_m macro_f1(base_m)`。负值 = stacking 比最好的单模型差。
3. **困难簇**由机械规则导出，不手工指定：`f_ij = CM_rf[i][j]/rowsum(i)`（按任务取均值），
   `max(f_ij, f_ji) >= TAU = 0.10` 连边，取节点数 ≥2 的连通分量。
   自采上恰好给出 `{Light_T1, Light_XM, Sensor}`，成员 f 值 0.149–0.897、非成员 0.069–0.095。
4. **簇内源域 OOF 可分性**（简称可分性）= RF 在**源域 OOF** 上、只算簇内那几类的 macro-F1。
   纯源侧，不用目标标签。**数值低 = 簇越难。**
5. **共识推翻率** = 在三个基模型**预测一致且正确**的窗口中，stacking 改判的比例。
   零建模假设，不依赖任何系数解释。
6. **`|S|`** = 源环境数。自采有 6 个环境（R2/R3/R4 normal，R5 位置变更，R6/R7 操作抖动），
   G0 网格跑了全部 30 个有序环境对 + 多源组合 = 162 任务。

## 3. 四层的证据与状态

### 层一 · 表示（自采，已测）

94 维特征里 33 项是 802.11/radiotap 专属（16 个 `subtype_*`、8 个 `rssi_*`、retry、
ctrl/mgmt/qos_data/null_data 等），加 2 项以太网上恒零列，共 35 列。删掉得 `strict59`。

```
预冻结门 MULTI_MODEL_BRIDGE_SUPPORTED（5 模型 × 5 种子 × 350 模型单元）
  等权 ΔLORO        +0.1056   （门槛 +0.02）
  等权 Δ最差LORO     +0.1644   （门槛 +0.02）
  5/5 模型 LORO 改善
  RF 历史对照最大误差 0.000e+00
Stacking 的 LORO gain（3 任务 5 种子均值）  -0.1700 → -0.0093   消失 94.5%
代价  ΔSingle -0.0699 ~ -0.1075   ΔJoint -0.0788 ~ +0.0308
rssi_* 占 RF 重要性质量 27.4%，排 #2/#3/#4，selected_rate 恒为 1.0
```

**没测**：35 列是整组删的，**哪一族在起作用完全未知**。所以"采集条件量"目前只是这一组的名字，
**不能说"RSSI 是主因"**。`NO_RSSI` 单独臂还欠着。

这是转变后最强的一环。四组互相独立的测量：

**(1) 共识推翻率——零建模假设**

  Camera    一致且正确 333  被推翻   0 =   0.0%
  Socket    一致且正确 368  被推翻   0 =   0.0%
```

**(2) 损失完全定位在簇内**

```
逐类 F1（同任务）        rf     xgb     lgb    STACKING
  Camera               0.923  0.939  0.938    0.932
  Light_T1             0.540  0.526  0.545    0.175

注意最后一行：**三个基模型在簇上只差 0.0077,而 stacking 掉 0.226。**

**(3) 加权解释被实验排除**

```
最佳基模型 lightgbm                    0.666180
equal_soft      等权投票                0.666025   gap -0.000155
meta_soft       元学习器逐模型权重       0.666602   gap +0.000422
meta_soft_cls   元学习器逐(类,模型)权重  0.664789   gap -0.001390
stacking        完整元学习器             0.440629   gap -0.225551
```

三种权重分配（含元学习器自己的权重）**全部落在最佳基模型 ±0.002 内**，只有加上**跨类项**的那一档掉下去。
三任务均值：equal −0.0294 / meta_soft −0.0255 / meta_soft_cls **−0.0058** / stacking **−0.1741**。
即元学习器的权重分配是它**做对**的部分，跨类映射是**做错**的部分。

**(4) 与独立线 EC-MDM 的交汇**

独立线（另一条并行研究线）测的 EC-MDM 是"固定源元层 `S` 与 oracle 目标重拟合元层 `F` 之差"的
可恢复结构，其嵌套适配器阶梯：

```
I 类别阈值（4 参数）              ER 0.4416
G 类别阈值 + 全局块缩放（7 参数）   ER 0.6752
C 类别阈值 + 类别条件块缩放（19）   ER 0.8910   ← 首个充分阶段，6/6 环境
F 完整 target-CF 元层             ER 1.0（定义为上界）
UNSW 外部复现（M3）：MMG_ood 0.0132、excess 0.0121、C 级 ER 0.8343、3/4 环境
```

而上面 (3) 里的 `meta_soft_cls` **就是 C 级 19 参数里的那 15 个块缩放系数**（没有 4 个阈值那一半）。
分母不同（M2 的分母是有标签上界，(3) 的分母是相对最佳基模型的损失），
但**排序和结论一字不差:全局分辨率不够，类别条件才够**。两条独立路径在同一个数学对象上碰面。

**UNSW 的预注册检验失败**：四条签名（定位/免疫/系数/regime 错配）实测 2/3、3/3、0/3、2/3，
`|gap_H|` 三任务均值 **0.009929** 而预声明区间是 0.03–0.20 →
判定 `MECHANISM_NOT_EXTERNALLY_REPLICATED`。此判定不因后续解释而改变。

**事后（判定之后才提出，按先例不得升级为确证）**在 UNSW 上测共识推翻率：
困难簇 **12.9%**（633/4900）vs 易类 **0.07%**（28/43031），集中比 **185×**，
去向是簇内伙伴（BelkinWemoMotion ↔ BelkinWemoSwitch）。
即**定性形态在，定量严重度不在**，而后者与 UNSW 的可分性（0.459–0.556，网格第 26–48 百分位）一致。

### 层四 · 症状（已判否为定量解释变量）

`CPD_y`：行归一化混淆矩阵漂移，算在 RF 上。作描述可用；作定量解释变量已判否（见 §1）。
另有一个代数问题：行归一化后每行离对角质量恰等于 `1 − recall_i`，**代数上内含误差幅度**，
所以它与"F1 下降"的高相关有一部分是必然的。

## 5. 一个必须知道的通约性限制

自采（802.11 空口）与 UNSW（以太网网关侧）的 61 个"共有"特征**同名同代码路径，但不是同一个物理测量**：

```
p10–p90 区间重叠 / 并集：  34/61 列 < 0.20    仅 11/61 >= 0.50
interarrival_p10   自采 1.669e-06  vs  UNSW 0.02297   13,700×
byte_count         5694            vs        458          12×
窗口内包数中位      28              vs          4           7×
other_packet_ratio 均值 0.310（802.11 管理/控制帧，UNSW 上不存在，且占比逐类不同）
```

`interarrival` 差 3–4 个数量级的原因：自采是空口抓包且不过滤，802.11 ACK 紧跟数据帧、间隔在 SIFS 量级。

**后果**：跨数据集只允许比较**方向与结构签名**，**不允许比较幅度**，不允许跨数据集特征重要性对照。
所以"UNSW 是自采的四分之一强度"这种说法**不成立**，应改为"同符号、同结构，不同测量系统，幅度不可通约"。

## 6. 已发现的两个实现缺陷（都还没修）

1. **CORAL 基线的着色矩阵转置错误。** 行向量约定下 `X_aligned = X_c @ inv(L_s.T) @ L_t` 得到
   `Cov = L_t.T @ L_t`，而目标是 `Ct = L_t @ L_t.T`；应为 `L_t.T`。
   落盘的 `cov_reduction_pct` 是 **−113% ~ −886%**（协方差差异被放大 2–10 倍），
   而正确实现按构造应 ≈ +100%。所以 2026-06 那份"CORAL 让 macro-F1 暴跌 37.75%、
   说明全局协方差对齐不是瓶颈"的推断**不成立**——域适应这一族在本项目数据上**从未被真正检验**。
2. **自采 `up_*` 特征族退化。** `up_packet_ratio == 0` 的窗口占 **79.9%**，`up_len_std` **100%** 为零；
   逐类均值 Camera/Light_T1/Light_XM/Sensor **全为 0.0000**，只有 Socket 是 0.4005。
   对照 UNSW 同族恒零占比 0.005。方向判定用的是 TA/DA 对 BSSID（tshark 3.2.3 不暴露 ToDS/FromDS）。
   **这让 `up_*` 成了近乎完美的 Socket 检测器，而 Socket 在所有模型所有任务上 F1 恒为 1.000**——
   "易类免疫"对 Socket 那一格需要重新论证。待查。

## 7. 硬约束

- **不重新采集自采数据**（用户已决定）。设备面板固定为 5 台，每类 1 台。
- **服务器不配置任何代理**，所有网络操作走校园网直连。
- **冻结协议纪律**：任何产生判定性数字的实验必须先写协议（先写后看）、在登记表登记、
  跑完补结论；历史文档加注降格、从不删除；不得因结果不利而改判据。
- 目标 2026-12 投稿，主投 IEEE TIM（测量类，scope 匹配"口径决定结论"，不要求提出新方法）。
- **不存在可用的公开 802.11 空口数据集**：UNSW、CIC-IoT-2022 均为网关/交换机侧有线抓包，
  无 radiotap → **层一在公开数据上结构性不可复现**。射频指纹类数据集（SMoRFFI、WiSig 等）
  是原始 I/Q 前导码样本，层次不对，提不出本项目的特征。

## 9. 最想要外部意见的几点

1. 四层链条里，**层一→层二那条箭头目前是"推断，未测"**。补它的方式是在 strict59 表示下
   重算簇内源域 OOF 可分性。这个设计有没有更强的替代？

   对测量类期刊够不够？还是必须做成定量预测才站得住？

   这个组合在 SCI 二区（主投 IEEE TIM）可辩护吗？
